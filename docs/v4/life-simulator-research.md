# v4 内容架构研究：从“事件日志”到“人生场景”

日期：2026-10-31。  
性质：架构审计与研究结论，不是实现完成报告。  
结论先行：**现有个人生活/叙事层不应继续修补。** 当前系统把世界状态变更日志当成故事，再用模板或散文层包装；继续加过滤器、加年龄判断、加一个 prose 层都会重复同类问题。需要把“人生事件、场景、叙事、世界因果”拆成独立模型，重建个人生活管线。

## 1. 当前项目目标与文档冲突

仓库旧 `PRODUCT_SPEC.md` 描述的是：原创低奇幻世界、默认成年角色、20 分钟/世界年、玩家创建起点后旁观。  
用户当前明确要求的是：真实地球 1900、只创建新生儿、更快时钟、残酷历史、内容优先。

这不是小改动，而是产品合同变化。继续同时满足旧文档和当前体验，会导致：

- 出生流程仍按旧“成年角色/两阶段 LLM 编译”设计，阻塞创建；
- 世界包仍是旧奇幻默认，历史内容与地球包分叉；
- “一年一提交”与“立即进入游戏”被混在同一个写事务里；
- 文档说 20 分钟/年，环境却用 0.5 分钟/年，实际又受 1 年批处理阻塞。

**因此先冻结 v4 产品合同：**

1. 一个真实地球 1900 共享世界，历史是条件与压力，不是强制剧本。
2. 玩家只创建新生儿；出生应是一个即时事件，不等待 LLM 或年度模拟提交。
3. 玩家创建后立即进入观察界面；LLM/人生底稿/事件链在后台继续。
4. 个人生活以“年龄阶段 + 场景链”推进，不以月度状态日志推进。
5. 内容可以残酷、黑暗、怪诞，但必须有真实状态、年龄/角色约束和因果；不生成未成年人性内容或露骨性描写。
6. 不做旧世界/旧日志兼容；旧内容归档，不再作为新管线输入。

## 2. 参考系统：各自真正解决了什么

### BitLife（闭源商业产品，仅产品层参考）

**观察到的产品结构：** 随机出生属性、按年龄推进、事件卡/选择、属性与关系变化、职业/家庭/世代循环。公开商店页与玩家资料都强调“text-based life simulator / choices shape story”。

**应借鉴：**

- 创建后立刻开始，不把“生成人生”做成等待页。
- 年龄推进是主时钟；事件是年龄节点上的内容。
- 随机出身 + 可编辑起点，降低玩家创作负担。
- 属性/关系/职业结果要可见，玩家能理解“为什么变成这样”。

**不应借鉴：**

- 封闭事件池与纯 RNG 选项，没有共享世界因果。
- 事件只影响个人数值，不影响地区/组织/他人。
- 商业产品的内部实现不可见；不能把它的产品表现当作机制证据。

### Crusader Kings III（官方 modding 文档可读）

**真实机制依据：** 官方 `Event_modding` 页面说明 `on_action` 是代码在特定动作时执行的脚本入口；有 `trigger`、`random_events`、`first_valid`、`fallback`、延迟与权重；`scope` 决定事件能访问谁。

**应借鉴：**

- 事件是**作用域内的候选事件**，不是“每人每月发一条日志”。
- 事件可以延迟、可以有前置条件、可以不发生。
- 角色、地点、头衔、关系是显式 scope；角色名不是职业/身份校验。
- 事件链和后续事件用真实状态重新检查，不预写结果。

**不应借鉴：**

- 封建王朝专属的政治/头衔系统。
- 把玩家角色当中心；我们的共享世界不允许主角保护。
- 事件脚本规模直接搬进在线共享世界；需要索引、预算、候选上限和确定性顺序。

### Wildermyth（官方 wiki + 公开设计分析）

**真实机制依据：** 官方 wiki 的 Story Roles、History、Outcomes/Effects 说明：事件角色有 required/optional/forbidden 目标、评分阈值；History 可以附加可查询 Aspects；效果可分为测试、分支、触发后续。

**应借鉴：**

- **场景（scene）是一等公民**，不是日志句子。
- 角色绑定与真实状态分离：角色名只是绑定标签，必须用年龄/位置/关系/职业等硬条件验证。
- 关系事件（友谊、恋爱、竞争）由共同经历和角色适配产生。
- 永久历史必须留下可查询状态，不能靠扫描文本判断资格。
- 事件模块可以有多个结果和后续触发。

**不应借鉴：**

- 固定漫画 vignette 池最终会重复；需要程序化条件、地区/时代内容包和 LLM 只做受约束扩展。
- 队伍战术/战斗关卡不是我们的核心。

### Dwarf Fortress（官方 wiki 可读）

**真实机制依据：** 世界生成后生成历史，追踪文明、地点、人口和历史人物；Legends 模式按文明/人物/时代查看历史事件。

**应借鉴：**

- 世界历史是**实体 + 事件图**：人物、地点、组织、战争、灾祸、遗物、关系都有 ID。
- 具名人物与抽象人口共存；不要为了每个 NPC 写完整人生，但具名人物要有可追溯历史。
- 历史事件可以作为“传奇/传记”被查询，而不是只存在于运行日志。

**不应借鉴：**

- ASCII/深层物理模拟的复杂度；我们只需要人物、地点、组织、事件、因果。
- 让每个小事件都成为历史；需要 significance/聚合。

### RimWorld（公开 mod 代码可交叉验证分层）

**真实机制依据：** 公开 VEF 代码显示 storyteller 先计算 interval/incident，再 `CanFireNow`，最后 `TryExecuteWorker`；执行可能失败。

**应借鉴：**

- **调度者/事件作者/执行者分离**：提议事件不等于事件发生。
- 事件合法性在执行前重新检查；事件可以失败/不发生。
- 节奏由 director/storyteller 控制，不是每月固定发日志。

**不应借鉴：**

- 殖民地管理和以玩家损失为中心的强度调节。
- 个人事件不应由“戏剧性”直接决定死亡/胜利。

### The Sims（产品层参考）

**应借鉴：**

- 需求、关系、日常自主行为形成可观察生活。
- 事件的结果通过人物状态和关系表现，不是旁白宣布。

**不应借鉴：**

- 玩家直接下达日常指令；我们的玩家只观察。
- 现代郊区生活包；我们需要历史条件。

### Real Lives / Alter Ego / Chinese Parents / Growing Up（产品层参考）

这些作品共同证明：

- 随机出生国家/家庭/属性可以制造强烈代入感；
- 人生阶段需要不同事件池；
- 选择会改变长期轨迹；
- 玩家喜欢“可重开、可比较”的人生结果。

**应借鉴：** 随机完整草案、阶段事件、选择/后果、可比较的人生轨迹。  
**不应借鉴：** 把历史压成选择题测验、用固定事件表替代世界因果。

### Generative Agents / AI agent simulations（研究参考）

**应借鉴：**

- memory stream、reflection、planning 让 agent 能保持连续性；
- 观察必须来自角色可见信息，不能全知。

**不应借鉴：**

- 只有记忆/对话，没有出生、成长、历史结构和地方事件链；
- 让 LLM 直接决定事实或替代模拟器。

### lifeRestart / Fallen London storylets（开源/设计参考）

**应借鉴：**

- 年龄/条件事件池、天赋/特质触发、条件过滤、加权选择；
- storylet 用状态解锁后续，不预写整棵分支树；
- 事件定义与运行实例分离，记录触发次数。

**不应借鉴：**

- 单人回合、每年必选一个随机事件；
- 无界递归/无资源约束的事件链。

## 3. 我们的游戏应该是什么样

不是“带地图的 BitLife”，也不是“CK3 简化版”。产品承诺是：

> 一个真实历史压力下的共享世界。你写下一个新生儿的出生条件，然后看他/她在具体地方、家庭、阶层、时代事件中活成一条不可预写的生命。

核心循环应是：

```text
出生事件（即时）
  -> 生成“人生底稿”（条件化场景候选，不是固定未来）
  -> 世界按年推进
  -> 每年/阶段出现 0..N 个具体场景
  -> 场景有角色、地点、选择/被迫路径、即时后果、延迟后果
  -> 后果改变人物/家庭/地方状态，并可能触发世界反馈
  -> 死亡/年老/世界终结 -> 传记与历史归档
```

### 3.1 一层：世界事实

世界模拟器继续产生真实状态：粮食、价格、疾病、战争、政治、迁徙、组织。  
但这些**不是人物故事**，只是场景条件。

### 3.2 二层：人生场景（LifeScene）

每个场景必须是：

```ts
type LifeScene = {
  id: string;
  year: number;
  age: number;
  placeId: string;
  subjectId: string;
  participants: { personId: string; role: string }[];
  preconditions: SceneCondition[]; // 年龄、性别、阶层、职业、关系、地点、世界压力
  immediate: {
    title: string;
    description: string; // 具体事实
    choice?: SceneChoice[];
    forcedOutcome?: string;
  };
  effects: SceneEffect[]; // 真实状态/资源/关系/职业/健康/迁移
  delayed: DelayedSceneHook[]; // 后续场景/后果，不预写“多年后”
  worldLinks: string[]; // 本地事件/历史事件/组织/地点
  sourceIds: string[];
};
```

关键点：

- **角色显式**：caregiver/recipient、parent/child、employer/worker、officer/soldier、dealer/addict。禁止用 `personIds[0]` 猜主语。
- **时间阶段显式**：即时事实与延迟后果分开。新生儿不能有“伴随多年”的旁白，只有当前症状。
- **年龄门槛显式**：儿童不能加入成人组织、不能与任意历史成年人建立亲密关系、不能作为照护者。
- **地方事件链显式**：1918 孟买流感不是“普通居民承受影响”，而是学校停课、市场关闭、家庭成员感染、工资中断、葬礼、谣言、隔离、邻居死亡、孤儿/寄养等场景链。
- **事件内事件**：一个场景可以触发 1–3 个后续局部场景，但必须有独立条件、预算、因果和可失败性。

### 3.3 三层：叙事投影

叙事只读已提交场景/历史事件：

- 不负责决定事实。
- 不把内部状态（`identity_shift`、`agenda_*`）当故事。
- 不预告未发生的未来。
- 允许 LLM 扩写，但必须绑定 `sceneId`/`sourceIds`，关键事实（死亡、金额、关系、地点、年龄）验证。
- 安静年份只写已发生事实和可核验状态，不硬编“戏剧”。

### 3.4 四层：导演/世界线

- LLM 周期评估世界线偏移，提出**场景包/条件/局部事件**，不直接改人物。
- 局部 director 控制事件密度和类型，避免每月重复接济/加入组织。
- 历史人物只作为有年龄、地点、身份约束的参与者；不能给 7 岁儿童安排 80 岁历史人物密友。

## 4. 必须删除的旧架构

不是兼容，是替换：

- `packages/narratives/life.ts` 作为最终故事生成器；
- `life-trajectory/apply.ts` 直接把 branch summary 当事件文本；
- 所有 `identity_shift/agenda_*/career_progress` 进入正文的路径；
- 月度 `family_support`、`caregiving`、`joined` 直接成为年度故事；
- 出生阻塞 UI、等待模型/整年模拟批次的流程；
- “旧事件文本兼容”“旧世界日志修复”。

## 5. 要新建的最小垂直切片

先不做全球内容库。做一个真实的 1900–1920 孟买/柏林/上海（任选）儿童场景链：

1. 出生场景：家庭、阶层、住房、父母职业、婴儿健康（有真实先验）。
2. 0–6 岁：哺乳/断奶/疾病/兄弟姐妹/照护者死亡/寄养，每个场景有年龄门槛和具体家庭角色。
3. 6–12 岁：童工/学校/宗教/家族期待/地方疫情，不能出现成人组织 membership。
4. 12–18 岁：学徒/工厂/迁徙/战争/婚配压力/犯罪/性工作（成年后且非露骨）。
5. 1918 流感链：地方冲击 → 家庭具体场景 → 收入/照护/死亡/孤儿 → 后续 2–3 个场景。
6. 每个场景有 source/participants/effects、真实 state 变化、可查询事件。

验收不是“测试通过”，而是：

- 10 条随机人生逐条人工审查：年龄、角色、地点、历史条件、因果、文字具体性。
- 没有 3 岁入会、7 岁与任意历史成人密友、每年重复接济。
- 同一场景在不同家庭/地区产生不同分支。
- 初始 NPC 也有过去/未来场景底稿，不只是玩家孩子。
- 玩家创建后立即进入界面，出生事件和年份推进不阻塞。

## 6. 当前源码审计结论（需要替换而不是补丁）

- 事件 `personIds` 没有角色语义，导致 caregiving 主语反转。
- 事件 `data` 无场景/阶段字段，branch label（结果总结）被当即时事件。
- 社交/组织/加入没有年龄门槛，导致儿童与成人组织/历史人物乱连。
- 月度 support/agenda 日志被年度叙事选中，造成复读。
- 初始人物没有 LifeTrajectory；只有玩家新生儿有。
- 叙事层在事件之后追加模板/摘要，无法修复事件本身的错误。

## 8. 结论

当前问题不是“某几个事件写得不好”，而是：

- **没有场景模型**；
- **没有角色/年龄/时间阶段约束**；
- **没有地方事件链**；
- **没有把内容作为一等资产**；
- **叙事层在替错误事件擦屁股**。

继续打补丁没有意义。应保留世界模拟、存储、地图、历史资料和单写者，重建人生场景/人生引擎/叙事投影三层。
