# 世界人生 — 参考项目研究、实际测量、工程迁移与验收

这不是让 Codex 去照着 README「研究一下」的任务清单，而是本轮**实际查到的代码/脚本特征**、适用范围、可复用边界与未完成的调查清单。引用日期：2026-10-31。代码与许可证状态可能随版本变化。

## 1. 具体项目怎么做，我们能借哪一部分

### A. 人生重开模拟器（Remake）——适合年龄内容，不适合多人世界核心

- 仓库：https://github.com/VickScarlet/remake
- **实际查看源码**：`packages/core/src/event.ts` （主分支，约 53 行）；其中 `check(event,state,profile)` 从 `@remake/data` 取得 `include/exclude/NoRandom`，通过 `@remake/condition` 筛选；`trigger(eventId, state, profile)` 应用 `LIF/AGE/CHR/INT/STR/MNY/SPR` 等状态效果，之后依次检查 `branch` 并递归触发后续事件。
- 可借：事件数据与代码分开、条件筛选、加权事件、分支执行、天赋与年龄阶段。
- 不能照搬：这套核心效果主要是单人物属性更改，不保存另一名实际存在人物的雇佣、亲属、承诺、社会认知与组织权限。我们的事件可以借其**内容管理与分支思想**，不能仅把数值效果换个名字就叫社会模拟。
- 直接复用代码？其部分代码与数据可以进一步查许可证；应对特定文件和依赖做法律检查，再定 copy/port/only-reference。

### B. Wildermyth ——目标选角、人物永久经历、场景驱动

- 数据格式：https://wildermyth.com/wiki/Data_Format_Overview
- Target Matching：https://wildermyth.com/wiki/Targets_and_Scoring_Guide
- Story Inputs/Outputs：https://wildermyth.com/wiki/Story_Inputs_and_Outputs
- 实际机制：事件指定 `hero`、`lover` 等角色；Required、Optional、Forbidden 角色与分数门槛；角色性格、关系、History、地点和公司历史影响可否成戏。`History` 可以永久添加/移除 `Aspects`，进而改变人物后续技能和事件资格。
- 可借：**先寻找实际参与者再发生故事**；历史记录不只是文本，还改变未来行为；系统要能解释为什么一个故事无法触发。
- 不能照搬：它的主要活动规模是队伍冒险，不适用于按同样精度逐秒更新 30k 位人物，也没有我们想要的近代人口与国家经济。
- 复用决策：取设计与字段语义，商业游戏内容/素材不直接复制。

### C. Cataclysm: Dark Days Ahead ——成熟可执行条件内容

- EOC 文档：https://docs.cataclysmdda.org/JSON/EFFECT_ON_CONDITION.html
- 实际机制：`ACTIVATION`、`RECURRING`、`EVENT`、`NPC_DEATH` 等类型；`required_event` 绑定真实引擎事件；`condition/effect/false_effect`；`context_val` 引用事件携带的实体与参数；`time_in_future` 延后执行；支持多条 EOC 组合与变量作用域。
- 可借：触发、作用域、条件-效果、可持续/延迟、事件带来的上下文必须可在新规则中访问。
- 不能照搬：游戏偏向末日生存、物品/地图/人物局部交互；没有 1900 年真实地球的户籍、国籍、经济与政治制度；部分 EOC 能力具有过大的作用范围，不能无边界暴露给 LLM。
- **许可证注意：** 项目官方说明代码和数据总体采用 **CC BY-SA 3.0**，包含 share-alike 义务；最新贡献指南明确不接收 LLM 生成内容的贡献。这是我们**参考机制而非直接复制其源码或给其提交生成内容**的重要原因。详见 https://cataclysmdda.org/contributions/ 和 https://github.com/CleverRaven/Cataclysm-DDA/blob/master/CONTRIBUTING.md。

### D. Crusader Kings III ——角色范围与事件分发，非可移植引擎

- 社区脚本信息：https://github.com/jesec/ck3-mod-base/blob/master/base/game/common/on_action/_on_actions.info
- 模组机制：https://github.com/jesec/ck3-modding-wiki/blob/master/wiki_pages/Event_modding.md
- 实际机制：内核触发 `on_birth_child`、`on_death`、`yearly_playable_pulse` 等；Action 会带角色 Scope，脚本决定可触发什么。文档警告在对每位人物调用的周期钩子里再次遍历所有活人，可能引入 N² 级工作量。
- 可借：角色/家族/领地/组织范围；角色拥有任职与权力、继承、复杂关系；以具体事实触发故事，不靠随机日志；按人口范围设置低频脉冲。
- 不能照搬：封建法理与头衔体系不等于 20 世纪国家、企业、党派、军队和福利制度；引擎与商业素材并非开源可移植组件。

### E. FreeSO / SimAntics ——行为队列与对象提供行为

- 仓库：https://github.com/riperiperi/FreeSO
- 实际工程：The Sims Online 的 C# 重实现，包含行为虚拟机/对象交互体系；仓库标注 MPL-2.0，具体代码可查 `FSO.SimAntics` 及相关执行部分。
- 可借：地点/物体/组织向人物**提供具体行为**，有中断、恢复、交互请求、队列；不要给每个人写一份包含全世界所有行为的超级 AI 决策树。
- 不能照搬：房屋局部空间中的高频行为脚本和实时动画，与 30 秒推进一年的跨地区社会史模拟完全不同。应借**语义/调度模式**，不是照搬每秒 Tick 的游戏完整 VM。

### F. RimWorld ——可控事件与外生冲击

- 可参考事件结构：https://github.com/Dev-Jahn/rimworld-modding-reference/blob/main/05-events-incidents/incident-system.md （第三方整理，非官方源代码）
- 具体概念：IncidentDef 的执行器、发生条件、冷却与难度/威胁权重；Storyteller 调节重大事件节奏。
- 可借：外生事件并非总靠个人动作自然涌现；强历史导演可以创造危机、机会与巧合。但本项目不能因“世界不够刺激”每隔几分钟强行投灾祸。
- 不能照搬：RimWorld 的难度调节经常围绕单个玩家殖民地；本游戏是一万人共享且不保护主角的世界，不能专门针对观察者作弊。

### G. OpenVic-Simulation ——开放式宏观人口/经济工程参考

- 仓库：https://github.com/OpenVicProject/OpenVic-Simulation
- 已见事实：该仓库具有 C++ 模拟库、数据加载子模块、headless 构建与单元测试/可选基准流程；使用 MIT 许可证，项目仍在开发。
- 可借：POP/社会阶层与生产模型的状态组织方式、数据校验和无 UI 仿真/基准工具。
- 不应宣称它是可以直接替换现有世界经济的成熟完整组件。技术栈、时代不同，且目前仓库还需实际读更多内部代码才能决定可否移植。

### H. AgentSociety 与 Generative Agents ——LLM 是稀缺认知资源

- AgentSociety 研究：https://arxiv.org/search/?query=AgentSociety&searchtype=all
- Generative Agents：https://arxiv.org/abs/2304.03442
- 研究价值：说明记忆、推理、反思、环境交互的某些能力可由 LLM 支撑；也展示大规模 LLM 智能体的计算与推理代价并不属于普通单机游戏逻辑范围。
- 对本游戏的结论：不让每个角色按月调用 LLM；出生编译、内容族生成、稀有深度重规划和世界导演是优先业务。具体 AgentSociety 吞吐数字只能按论文设备配置理解，不可直接外推至 6 vCPU VPS。

## 2. 历史数据：该拿什么来校准，不该拿什么来播剧本

| 数据 | 适用 | 注意 |
|---|---|---|
| Human Mortality Database https://www.mortality.org/ | 历史不同年龄/性别死亡率、寿命与婴儿风险 | 覆盖国家与年份不一致；不能把有资料国家的率全球照搬 |
| Maddison Project Database 2023 https://www.rug.nl/ggdc/historicaldevelopment/maddison/releases/maddison-project-database-2023?lang=en | 长期经济体量与收入级别，支持地区宏观校准 | 历史经济估算含模型与不确定性；附带 CC BY 4.0 及引用要求 |
| Correlates of War https://correlatesofwar.org/data-sets/ | 国战、外交军事冲突统计和分析框架 | 只能校准战争规模与发生倾向，不能强制未来按史实发生 |
| UN WPP 2024 https://population.un.org/wpp | **1950 年以后**人口宏观趋势对照 | **不覆盖 1900 年开局人口**；不能误称它能直接提供完整 1900 基线 |
| Wikidata https://www.wikidata.org/ | 历史人物名录、出生地、国籍、来源链接等初步索引 | 数据质量与时段误差较大，不能把所有目录人物当活跃模拟对象 |

**真实历史的重建和架空历史必须区分**：1900 baseline 逐项有来源，1900 年以后的历史事件变成条件化历史可能性。Director 的“回归”是创建新的**现实条件**，不是让史实自动复现。

## 3. 本次真正运行过的计算测量

之前已有 `sim_kernel_load_probe.py`，本轮在当前容器**重新执行**：

| 输入 | 人物月激活 | 有向关系 | 事件候选检查 | 事件匹配/简化交互 | 墙钟 |
|---|---:|---:|---:|---:|---:|
| 20k 人，8k 条规则，1 年，优先本地关系 | 240,113 | 146,712 | 3,769,576 | 同城互动 40,284 | 约 1.13 s |
| 40k 人，8k 条规则，1 年，优先本地关系 | 480,313 | 293,856 | 7,510,737 | 同城互动 80,367 | 约 2.91 s |

测试命令：

```bash
python sim_kernel_load_probe.py --actors 20000 --years 1 --rules 8000 --local-ties
python sim_kernel_load_probe.py --actors 40000 --years 1 --rules 8000 --local-ties
```

**这不是游戏引擎 benchmark。** 它只是 Python 内存里的简化预约调度和规则索引探针，完全没有人口守恒、雇佣合同、婚姻、真实社会关系、多方项目、战争、SQL 持久化、LLM 及浏览器请求。既不能据此保证 30 秒/年能跑 40k，也不能以它证明现有 Codex 项目具备社会模拟深度。实际运行还可能受服务器 shared vCPU fair-share 影响。

这次从数学上发现的更大风险是：30 秒/年导致 **一天 2,880 模拟年**，如果保存“每人每年一条永久事件”，20k 人就会在一天写出 5,760 万条日志；比单次事件匹配吞吐更容易成为瓶颈。请把主预算放在**有意义的状态压缩、历史归档和 LLM 调度**，而非炫耀每秒过多少 Tick。

## 4. 现有 Codex 仓库的增量审计矩阵

目前仅知道 Codex 自述：约 7,239 城市、28,711 历史人物目录、年龄/家庭/组织/战争/经济/历史/浏览器/持久化/异步 LLM；**未直接审计实现**。应在仓库中按以下问题找源码和运行证据：

| 主题 | 如果已有的正确能力 | 若没有，应升级成什么 |
|---|---|---|
| 人口 | POP 与具名人物共享人数和死亡账本 | Materialization/出生/死亡/迁移的守恒账本 |
| 家庭 | 具体监护、资金归属、抚养和跨代资产 | 家庭经济/监护合同，不止关系 `parent_id` |
| 职业 | 雇佣机构、薪水来源、职位权限、同事 | 真实雇佣合同与持续劳动过程 |
| 关系 | 双方独立认知、共同经历、承诺、秘密 | 方向性 Relationship/Knowledge 与历史绑定 |
| 人物互动 | 具体对象、请求-答复、条件、延期 | 多方 PendingInteraction 与事务状态机 |
| 组织 | 真实职位/权力/预算/项目 | 组织决策与个人行为联通的角色系统 |
| 事件 | 多角色匹配、条件、持续过程、版本、索引 | 参考 Wildermyth + DDA + CK3 重新组织规则执行器 |
| 历史 | 个人行动能推动具体法律、战争、人口与组织变化 | 个人—组织—宏观历史双向结算 |
| LLM | 出生预演、动态事件发布、导演、异常能力受控执行 | 分队列与权限分层的编译生产线 |
| 性能 | 实测 VPS 的 CPU/IO/RAM/历史容量和模型预算 | 同规则加速、完整历史容量模型及自动化长跑 |

> 如果现有代码在任一处已具正确的领域实现，优先保留而不是再写一套类名；若它只有数值补丁与随机日志，允许做必要的领域重构。

## 5. 交付顺序应按机制闭合，不是按功能数量

| 阶段 | 代码/内容产物 | 必须在同一世界实现的可观察后果 |
|---|---|---|
| I. 社会事实底座 | POP/具名身份一致性、家庭和工作契约、角色权限、事件/状态日志 | 工资、死亡、婚育不重复结算；家庭经济真实影响机会 |
| II. 交互与持续事务 | 行为提供、具体人物选角、请求-答复、事务/项目时间线、认知 | 两个现实人物不靠随机事件也能形成长期关系及合作/冲突 |
| III. 内容运行时 | 受控 EOC/多实体 Effect、角色匹配、延迟进程、版本与索引 | 同一事件族在不同地区、时代、人物上产生不同后果 |
| IV. 出生与祝愿 | LLM 出生推演、Birth Contract、特殊能力、异步编译/入世 | 祝愿能影响实际认知/人物关系，并与真实历史后果交织 |
| V. 20 世纪世界史 | 历史资料基线、战争/经济/政权/健康风险、真实人物活化 | 一项劳动法能改变后来多代人的真实行动选择 |
| VI. 生成式内容工厂 | 批量主题内容、持续动态自动发布、强 Director | 世界出现新技术/组织后事件库自动长出新的现实活动 |
| VII. 完整体验与上线 | 三栏、复杂纸娃娃、因果日志、离线回放、死亡总结、部署监控 | 人生能够从出生到死亡完整阅读，关键经历能追溯真实因果 |

不建议按这个表把系统隔离开发到最后才合并。每阶段需在同一个仓库运行完整跨模块因果场景、形成可复现运行证据；所有调查、单测和恢复工作由 Coding Agent 完成，不应要求玩家每天当测试员。

## 6. 容易误入的八个坑

1. **事件越多越好**：无法被真实角色/时代匹配的内容毫无价值。
2. **地名越多世界越真实**：没有家庭、工作、社会活动场所，7,239 座城市也只是地图点。
3. **所有 NPC 都必须用 LLM**：会击穿成本与可复现性，但不增加同等比例的真正互动。
4. **匿名人口等于不重要人口**：匿名居民必须真实生产、迁徙、死亡并参与组织，不然玩家无法改变历史。
5. **世界导演等于写故事**：导演负责改变世界条件与机会，不是撰写已发生的假历史。
6. **真实历史人物等于目录名称**：历史人物必须有行动窗口、真实社会关系与偏离史实的能力。
7. **异能平衡等于 fame 上升**：隐蔽读心、记忆操控和全球级治疗对世界的外部影响不能靠“被人关注”自动平衡。
8. **加速测试等于降低完整性**：削减人口可以，不能用删掉经济、政治、监护或战争的方式让模拟跑快。
