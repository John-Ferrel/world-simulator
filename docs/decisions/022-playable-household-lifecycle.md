# ADR 022：可玩版本的家庭容量、死亡与求偶生命周期

日期：2026-11-02  
状态：接受  
相关：`packages/v4/engine.ts`, `packages/v4/birth.ts`, `packages/v4/content/vienna-family.ts`

## 背景

在活动世界 1977 年审计中发现：

- `hh-lechner` 的 `memberIds` 有 88 条，其中 63 人仍在世；
- 出生事件文本显示“家里现在有 85 口人”；
- 已故人物的 API 年龄按当前世界年份计算，出现 129 岁；
- 求偶场景在 1918、1920、1921、1924 年重复出现，因为条件只排除“同住伴侣”，没有排除已有伴侣；
- 生育场景 `rate: 1` 且只冷却 1 年，导致同一家庭几乎每年新增一个孩子。

这不是内容不足，而是家庭/死亡生命周期缺少容量和状态约束。

## 决策

1. `Household.memberIds` 保留历史成员记录，不因死亡删除；但“当前住户规模”和住址容量一律只统计 `!person.died` 的成员。UI 可以继续显示已故家属。
2. 玩家新生儿选择一个真实存在的家庭：优先有 18–45 岁在世女性监护人、其次有在世男性成人、再按当前在世人数和家庭的稳定 ID 排序；住址已满的家庭不再接收新生儿。
3. 出生效果在住址容量已满时拒绝创建 Person，并记录警告；正式内容同时用 `householdSize` 条件在场景层阻止。
4. 求偶只允许没有任何未结束 `partner` 关系的成年人物；求偶冷却提高，禁止已有伴侣但未同住的人再次求偶。
5. 生育/父亲场景使用较低的年度发生率、2–3 年冷却和 `householdSize` 上限，不再每年机械生育。
6. 监护人死亡时，从同一住址的在世成人中补选监护人；死亡者的 guardian 身份从 household 的当前 guardian 列表移除，但 `parentIds` 和家庭历史保留。
7. 已故人物的 API `age` 固定为死亡时的年龄；死因和事件标题在 API 投影层本地化，不改变原始历史事实。
8. 本决策不删除、不重写旧世界。已有异常 household 只作为归档审计证据，新世界应用新规则。

## 替代方案

- 直接删除死亡成员：会让个人日志中的家庭历史消失，也会让“父母已故”无法从家庭记录读出，拒绝。
- 无限提高每年具名化/出生上限：只会放大错误，拒绝。
- 在 UI 隐藏死者和异常家庭：掩盖状态错误，拒绝。
- 为每个家庭建立完整住房市场：超出本轮可玩版本范围；先用容量约束和真实家庭选择，保留未来扩展。

## 迁移补充

旧数据库的 `v4_macro_proposals` 由早期 `CREATE TABLE IF NOT EXISTS` 创建，缺少后来使用的 `world_year` 列；`005_v4_macro.sql` 本身没有补列。新增 `infra/migrations/007_v4_macro_world_year.sql` 做 additive `ADD COLUMN IF NOT EXISTS`，并把 `V4_MIGRATION_VERSION` 提到 7。真实启动中该迁移修复了 Director enqueue 的 `column "world_year" does not exist`。

## 后果

- 新世界家庭规模受住址容量限制，人口增长会变慢；这比机械出生更可信。
- 玩家新生儿更可能进入有年轻父母的家庭，减少出生即孤儿。
- 部分旧世界仍会显示 63 人家庭；这是历史状态，不回写。
- 需要在 `v4-player-life`、`v4-vienna-family` 和浏览器 e2e 中加入容量/年龄/冷却回归。
