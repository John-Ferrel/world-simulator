# ADR 020 — Phase 3：宏观参数、统计死亡与 LLM Director

日期：2026-11-01  
状态：accepted  
相关：`docs/v4/phase-3-report.md`、`packages/v4/macro.ts`、`packages/v4/statistics.ts`

## 背景

Phase 2 的内容和事件运行时通过测试，但人口/历史模型不成立：老年死亡靠一次性内容场景；战争、流感、婴幼儿和产妇死亡缺少统一风险；事件池没有宏观治理；LLM 只参与出生契约和离线内容。继续调场景 rate 只会掩盖层级错误。

## 决策

### 1. 宏观状态是数据，不是控制结果

`MacroState` 只保存归一化的地区条件：战争暴露、粮食、卫生、医疗、稳定度、迫害、技术、疫情和迁移压力。它不直接保存预期寿命或年度死亡人数。寿命和人口结构是统计引擎运行后产生的指标。

### 2. 统计引擎是所有基础自然死亡的唯一入口

- 年龄/原因别基础风险；
- 地区/职业/军事/产妇/婴幼儿暴露；
- 卫生、粮食、医疗、技术、战争、疫情修正；
- 竞争风险采样；
- 所有死亡最终通过同一个 `death` effect / `applyDeath` 提交；
- Phase 3 世界不允许普通 `health` 伤害把 vitality 归零来制造第二条死亡路径；
- 明确的工伤/战争/暴力等外部 death effect 仍保留为独立事件，但不能重复杀死已死之人。

### 3. 聚合人口与具名人物分离

背景人口按地区/年龄段维护，不创建 Person；具名人口单独计数。总人口 = 具名 + 未具名。当前没有具名化流程，这是已知缺口，不用一个隐藏的“全人口 Person”数组掩盖。

### 4. LLM 只提出有界 proposal

Director 读取紧凑快照，输出 `MacroProposal`：参数增量、事件池政策、高层 developments。服务端重新验证 schema、范围、地区、时间、事件族和世界状态；合法 proposal 自动应用，失败/超时沿用旧 macro，不阻塞时钟。迟到 proposal 不影响已提交历史。

### 5. 事件池政策与内容工厂分离

`EventPoolPolicy` 只启用/停用/加权已注册事件族，并带地域/阶段/来源/版本。它不直接插入事件文本。`macroContentGaps` 把宏观条件映射成内容缺口，Content Author 生成候选包，验证后写入内容库。新内容不会自动按数量线性提高事故率。

### 6. 历史基线是夹具，不是现实强制

`VIENNA_1912_TIMELINE` 不再由模拟器强制应用。默认 macro 是 1912 基线；历史战争/流感/危机只由 Director、显式测试夹具或运维命令引入。这样可以测试无战争架空世界线。

## 替代方案

- **只修老年死亡场景/调 rate**：拒绝；仍是内容层，无法处理战争、婴儿、产妇、疫情和地区差异。
- **让 LLM 直接写死亡事件**：拒绝；无法审计、会改写过去、会把模型文本变成权威效果。
- **把预期寿命直接作为参数**：拒绝；因果倒置，无法解释具体人群/原因。
- **为全体人口创建 Person**：拒绝；本轮不构建全球 POP；先用聚合队列验证规模。
- **把模拟器改成全量增量事件存储**：推迟；本轮先打通宏观→风险→事件，不改整体持久化契约。

## 后果

正面：

- 真实 LLM 提案 → 验证 → revision-locked 持久化 → 统计事件链已跑通；
- 战争/粮食/卫生/医疗/疫情会改变风险，而不是只改一句文本；
- 基础死亡、感染/康复/恶化统一；
- 事件池政策实际影响 rate，content gap 已驱动生成战时内容；
- 四种历史情境和具名人生分开验证。

代价与限制：

- 参数/公式是粗粒度夹具，不是完整生命表或医学模型；
- 背景人口没有具名化/迁移闭环；
- Director 只验证了单地区/单年代；
- 20k 具名规模、全球多地区、生产部署未完成；
- 事件池政策过滤未知 family 时没有完整 warning 呈现；
- 内容工厂仍需要人工/CLI 审核，不是无人值守运行。
