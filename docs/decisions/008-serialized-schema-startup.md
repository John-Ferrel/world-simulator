# 008 — 服务启动只检查已应用的数据库迁移

浏览器验收发现 API、模拟器和 worker 同时热重启时，原先每次启动重跑的 `001_initial.sql` 会执行删除/创建触发器的 DDL，与其他服务或正在提交的事件事务形成死锁。

迁移现在使用专用连接、事务级 advisory lock 和版本标记。同一数据库的迁移串行执行；完整脚本与版本 2 的 SHA256 标记在同一事务提交。旧版本 1 的标记位于原脚本中段，不能证明后续表和触发器都存在，因此只执行一次兼容升级。后续启动只读取并检查版本和内容 hash，不修改表或触发器。已应用脚本内容变化会明确报错，未来结构变化应增加新迁移。

没有采用单纯重试死锁：它仍会让每次服务启动阻塞共享世界提交。也没有删除不可变历史触发器来回避锁。

数据库回归覆盖并发旧库升级，以及持有事件表读锁时的并发已应用迁移；后者使用短 lock timeout 验证没有隐藏的 DDL。
