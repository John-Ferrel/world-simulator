# v4 Break Update Plan — 世界人生 / Another History

状态：adopted。输入：`simulator-1031/01-04` + 用户确认。
原则：不做旧个人日志/旧事件文本/旧出生流程兼容。保留基础设施和 Earth 数据，重建领域层。

## 已确认

- 模型：继续使用 OpenCode Go key，开发期允许真实调用（至少 $40 额度）。
- 旧数据：归档旧世界；启动新的 1900 v4 世界。
- 首个切片：维也纳 1912。
- 范围：保留存储/认证/API/地图/Earth 数据；替换人物、社会、事件、场景、叙事、出生、内容执行层。

## 保留

- PostgreSQL、单写者/lease/fencing、事务、journal/outbox、recovery、backup。
- Fastify API、SSE、React/Vite/Pixi、纸娃娃素材。
- Earth 1900 地理、城市、人口、主权、历史人物目录、部分宏观资源/交通/战争基础数据。
- 已有 UI 的极简观察器方向，不保留旧日志模型。

## 删除/替换

- `World` 作为人物/事件的巨型 JSON 载体；替换为按领域拆分的实体/账本/事件存储。
- `HistoricalEvent` 扁平 `personIds + text + data`；替换为带角色、scope、causes、effects、followups 的事实。
- `narratives/life.ts` 最终日志生成器。
- `life-trajectory/apply.ts` 作为事件文本/后果生成器。
- `identity_shift`、`agenda_*`、`career_progress`、月度 `support` 进入正文的路径。
- 两阶段/阻塞式出生与旧 LifeProgram 适配。
- 旧世界、旧日志、旧兼容测试。

## 新领域层

```text
World / Calendar / TimePolicy
PopulationCell
Place
Household
Person
Organization / Position
Project
Interaction
Relation
Knowledge
HistoricalEvent (fact)
RuleDef / SceneDef
SceneInstance
```

不变量：人口/货币守恒、唯一历史、死亡不可逆、请求-答复分离、信息隔离、年龄/监护约束、规则版本隔离。

## 新运行循环

```text
到期宏观结算
-> 到期具名事务（工资/申请/治疗/学额/军役/项目）
-> 社会场所候选集合
-> Scene 选角（年龄/地点/关系/组织/制度）
-> 发起请求 / 人物或组织独立回应
-> 原子提交 effects + EventFact
-> 调度 delayed followups
-> 仅显著事实进入历史/日志
```

## 内容优先级

1. 维也纳 1912：家庭、住房、印刷工工伤、学校、教师、工会、赔偿、女孩是否辍学。
2. 1914/1918：战争征召、粮食、疾病、失亲、难民、照护。
3. 跨代：婚姻/生育、阶级流动、组织/法律变化。

内容单位是**机制族与场景链**，不是句子数量。

## 立即执行顺序

1. 冻结旧服务器与世界：旧世界归档，不再产生新日志。
2. 写 v4 domain/event/scene 合约，先测纯逻辑。
3. 做 Vienna 1912 最小世界和 8 个场景链。
4. 接新 API/UI，删除旧个人日志路径。
5. 接出生契约与 LLM，最后接内容工厂/导演。

在任何不能由规格和代码决定的产品取舍前，先问用户，不自行猜。

## 执行状态（2026-11-01 最终）

- 旧 `world-1/2/3` 与早期 v4 开发世界已全部归档；当前活动世界由 `pnpm dev` 播种/推进。
- v4 领域、引擎、内容、持久化、API、模拟器、出生愿望 worker 与三栏观察器已接通。
- 内容：19 个作者场景 + 19 个通用人生场景 + 4 个家庭/生育场景；10 个家庭、26 个具名人物、23 个地点、6 个组织、20 条来源、9 条公开时代记录。
- 引擎：纯年度推进、角色选角、缺失角色 blocked、类型化效果、角色相对引用、文本 token、死亡不可逆、同人同年场景去重、项目/交互生命周期、家庭经济。
- 经济默认开启。组织有显式月度外部营收，家庭有显式月度外部收入（抚恤/缝补/房租等）；工资、租金、食物和债务仍走账本。该外部部门是建模输入，不是凭空收入；没有完整市场/生产/税收/驱逐。
- 出生：立即写入出生事件；`v4_birth_contracts` 队列由独立 worker 调真实模型，校验严格 JSON 后只写读法、focus、≤4 个 ±0.08 性格微调和 taboo。失败最多重试 3 次，原愿望保留。真实调用已发生并验证，非 mock。
- API/UI：v4 API、认证、SSE、公开信息过滤、人物日志、家庭、关系、地图、时代、终点原因；`pnpm dev` 不再启动 v1–v3 服务。
- 验证：v4 七组测试 45 项通过；全量仓库 56 文件/325 项通过、28 项跳过（149.73 秒）；Playwright v4 流程 1 项通过；`pnpm build` 通过。最终数字以 `docs/v4/implementation-report.md` 为准。
