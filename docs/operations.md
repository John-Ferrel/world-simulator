# Operations

`pnpm admin status` reports active month/revision, authority lease, queues, settings and actual database size. `pause`, `resume`, `speed 20` change shared settings and write audit records. `close` submits a simulator command; it does not directly mutate canonical state. `verify` loads checkpoint plus journal and checks the canonical checksum.

`pnpm admin backup /secure/path/world.ndjson` writes a consistent repeatable-read **v2 streaming backup** of the fixed application table list, including canonical state/history, users, jobs, settings and sequence positions. It fetches one database row at a time, writes with backpressure, and publishes the completed file atomically without replacing an existing output. The header records format/schema metadata; an EOF footer verifies table counts and SHA-256. Truncated, extra, reordered, tampered or incompatible records are rejected. PostgreSQL performs JSON-to-column conversion to preserve large integers and timestamp microseconds.

The file is mode 0600 and contains password hashes/session records; use a private path. Restore into a **new empty, migrated database** with `DATABASE_URL=... pnpm admin restore /secure/path/world.ndjson`; occupied databases are refused. Stop application processes on the target during restore. A failed validation rolls the restore transaction back. The CLI detects legacy v1 JSON backups, with a 256 MiB total file limit; v2 is streamed with a 512 MiB per-record limit rather than an unlimited record size. Legacy files do not record sequence gaps and reconstruct sequences from rows; v2 preserves recorded sequence positions. Back up and restore via the application CLI; do not parse/rewrite the file with JavaScript tools that may round PostgreSQL integers.

PostgreSQL `pg_dump -Fc` / `pg_restore --exit-on-error` remains the preferred operational alternative for large databases. A completed dump alone is not evidence of recoverability: restore into an independent empty database, then run `DATABASE_URL=... pnpm admin verify` and compare the recorded world revision/checksum. Application v2 backups and PostgreSQL dumps are different formats; use the corresponding restore tool.

`verify` pins a world revision and checksum, selects an eligible checkpoint, and fetches each subsequent immutable journal row in sequence. It rejects gaps, incorrect previous checksums and a missing final row; later commits do not move its pinned target. The streaming SHA-256 encoder retains the existing canonical sorted-key byte format, so persisted checksums remain compatible. It avoids an additional full-world serialized checksum string, but a single state/patch still needs memory. This is bounded retrieval, not a claim of constant memory or unlimited world size.

The simulator lease expires after 15 seconds and is fenced within every commit transaction. A second writer cannot commit with the old owner/epoch. The wall-clock monthly watermark is committed with state, so restart processes overdue months in sequence without skipping canonical transitions. Log entries include lag and commit duration. Pause freezes world advancement; pending creation commands can still resolve until a world is closed. Running archives cannot be edited; epoch closure atomically seals the state and starts the next epoch unless `AUTO_NEXT_WORLD=false`.

Health: `/api/health`. Outbox cursor is monotonic across worlds, EventSource reconnect uses Last-Event-ID, and the API backfills committed events in order. Public streams contain public event facts only, not account ownership or private cognition. Browser read cursors are local and do not control shared time.

Schema startup is serialized by a transaction advisory lock. Version 2 marks the complete initial SQL script with its SHA256 hash, including tables and immutable-history triggers that originally appeared after the version-1 marker. Applied startup checks run without DDL; changing the applied script is rejected. Future schema changes need a new migration. World-pack metadata lives in each world independently of schema version. Journal recovery applies recorded state patches, not re-simulation.

Creation accepts an optional `Idempotency-Key` of 8–64 ASCII letters/digits/underscores/hyphens. It is scoped to a world; retries from the same account return the original command while another account cannot inspect or reuse it. SQL triggers reject event/journal edits and changes to already archived canonical worlds. In addition to the global revision, model proposals check their actor version, simulation deadline and consumed job ID.
