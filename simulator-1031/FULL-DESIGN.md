# 世界人生 / Another History — 游戏策划案 v1.0

**性质：** 游戏设计（Game Design）与内容设计。另见 `02-ENGINE-ARCHITECTURE.md` 的执行契约、`03-RESEARCH-AND-DELIVERY.md` 的证据与实施策略。

**设计基线：** 2026-10-31。此文是拟议的完整产品设计，不宣称当前 Codex 仓库已实现。文中安娜、约瑟夫等故事和数据均是**构造的游戏案例**，不是史实或运行截图。

## 0. 一句话、玩家到底在做什么

1900 年的真实地球，历史尚未确定。玩家创造一个**新生儿**：名字、性别、身体状态、外貌以及自由形式的祝愿。LLM 根据**此时真正的世界状态**深度编译出生契约及隐藏的可能人生。之后玩家基本不控制他。孩子在家庭、邻里、学校、职业、战争、疾病、婚姻、政治运动中自主生活，与其他玩家孩子、真实历史人物和普通 NPC 产生真实且持续的关系。有人早夭，有人平凡，有人建立企业、组织革命、改变战争或历史；死亡后留下真实人生档案与祝愿对照。

**三件中心玩法：** `人生模拟`、`小人之间的真实交互`、`个人与历史相互改变`。界面保持左人物—中日志—右地图的极简观察器。

**重要界限：** 这不是「角色成长游戏」（不指挥、不刷属性）；不是「互动小说」（历史共享且有状态守恒）；不是「LLM 对话酒馆」（不能靠说话直接决定结果）；也不是把地球大地图作为主要玩法的传统大战略游戏。

## 1. 已经确认的产品决策

| 决策 | 正式取值 | 后果 |
|---|---|---|
| 内容中心 | Person | 世界应首先体现在人的具体遭遇、共同生活及记忆里 |
| 角色入口 | 出生而非凭空出现成年人 | 孩子进入现存家庭、社区与人口账本 |
| 创建自由度 | 可编辑名字、性别、身体/外貌、自由祝愿 | 祝愿可为期望、异能、私有系统、禁忌或矛盾愿望，须深度解释 |
| 人物自主 | Radical | 出生设定不是永远不变的人格契约；没有主角保护 |
| 世界残酷性 | Harsh | 保留真实的婴儿死亡、战事、饥荒、伤病、屠杀与政治压迫；不是追求随机惨剧 |
| 历史起点 | 1900 年真实地球 | 地理、国家、人口、社会制度、历史人物以可追溯资料建立基线 |
| 历史偏离 | 真实 IF | 模拟发生后不强制跟随历史教科书；史实只作基线与吸引趋势 |
| 超常能力 | 少量真实异常个体 | 稀有、代价、范围、被社会发现的影响均是真实机制 |
| 新事件 | LLM 自动编译、自动入库 | 无须人工审核事件内容；编译失败的内容不进入生产 |
| 历史导演 | 强权限 | 可创造宏观冲击、历史人物相遇机会及结构性回归压力；行为必须留下干预账本 |
| 规模 | 10k+ 玩家注册/人物、另有至少 10k+ 具名背景人物 | 永久身份、较低频调度、聚合人口与持续社会网络 |
| 测试时间 | 30–60 秒/模拟年，可离线最大速率计算 | **缩人口不删系统**；正式世界速度作为可调整策略，不硬编码 |

## 2. 一个玩家进入游戏时看见什么

### 出生界面，不是角色构筑面板

示意（自由文本为核心）：

- `姓名`：埃莉诺·鲍尔（可自由输入，校验长度、违规输入，不强制历史常见名）。
- `性别与身体`：身体描述自由，结构化为出生性征、先天状况、感官与健康风险；不因“特殊”自动等于更强或更弱。
- `外观`：像素纸娃娃最初的外观，衣服与成长状态由世界改变。
- `祝愿`：「愿她听出一个人是否故意说谎；可她每次使用能力都会失去一段自己珍视的记忆。」

出生地、年份由**当前世界时间与可用出生家庭**决定；可以提供有限地区偏好，但不能凭空夺走活人的身份、头衔或财产。LLM 在后台解释祝愿，生成出生契约：原文、歧义解析、能力机制、限制、代价、表现形式、隐藏人生机会、出生所在家庭上下文。对人物的能力**保留原文与编译版本**，允许未来世界机制丰富后对不完整的愿望有新的解释，但不能暗改已使用的能力历史。

在正式提交前可以改出生信息与祝愿；提交出生事件之后不允许反向编辑曾经的出生事实。后续想法通过新生命或世界中的现实变化实现。

### 主游戏：极简，但信息真的存在

- **左侧：** 逐年龄变化的像素人物、衣着、职业、肢体伤残、婚姻或军职等少量高信息密度状态；不需要复杂人物管理表。
- **中间：** 按人的经历排列的时间线：普通生活、人物相遇、失败、记忆、社会与战争影响。事件可预览参与者和前因。没有真实后果的“今天又努力工作了”不应刷屏。
- **右侧：** 世界地图、人物在何地、地区与战争/经济/迁徙的变化。地图是解释人生，不是另一款策略游戏。
- **历史回放：** 世界只有一个当前时间；玩家可以停在自己的阅读进度，从出生开始看已发生的一生，不能改变共享过去。
- **死亡：** 不是游戏失败提示。展示生平、未完成之事、真实改变的人和组织、后代及出生祝愿对照。用户可继续观察后代或出生一个新孩子（具体账户额度由运营规则约束）。

## 3. 使「人生」变得具体的基础机制

### 3.1 一个人不是一包属性，而是参与中的生活

除了年龄、健康与性格，人物需要以下**可指向实际对象**的关系：

- **家庭**：谁共同生活、谁抚养、食物与租金谁承担、遗产与债务归属；婴幼儿不会独立找工作或参加政治活动。
- **教育**：就读的具体学校、科目、教师、资格、学费、考试、推荐；按时空制度决定可及性，不是 `education+1`。
- **职业**：雇佣合同的对象、职位、工资、工时、工作风险、工作场所、同事；无工作也不是简单的负数标签。
- **健康**：身体部位、疾病进展、治疗机会、成本、长期失能、照护；死亡率由年龄和当前环境风险决定，不能让两套系统重复杀人。
- **婚姻、亲子与亲密关系**：两个当事人有各自意愿和理解，社会制度约束婚姻可行性，孩子需要真实监护与人口结算。
- **政治、宗教、文化与阶层**：身份、组织成员、承担的义务、可参与的活动、受到的限制；不是 `ideology = liberal` 一个标签。
- **长期事务**：申请学校、寻职、追求某人、抚养孩子、申请赔偿、迁居、竞选、组织罢工、军事晋升；有参与方、进度、截止日、对手、条件变化与可中断性。

### 3.2 例子：父亲受伤，女儿是不是一定辍学？

游戏状态（**构造案例**）：1912 年，维也纳，印刷工 Josef 有雇主、班次、工资和家庭账本；其 12 岁女儿 Anna 在某所学校，有一名授课教师。

1. **工作事故**发生，来自工作地点的真实风险事件；伤害更新劳动能力，不直接修改女儿教育状态。
2. **雇佣结算**：原雇佣岗位无法继续，工资实际中断；伤病治疗需要真实支出。
3. **雇佣争议**：Josef 可以提出索赔；企业可以答复、和解或拒绝；在当地制度允许时可有法院、工会或保险参与。
4. **家庭账本**：储蓄、母亲收入、房租、家庭开支、赔偿和借贷共同决定实际收支缺口。
5. **教育连续性**：女孩会不会离校，取决于家人决定、学校制度、费用、她本人的意愿和已经存在的教师/亲属关系。
6. **共同世界后果**：同一工厂的另一名玩家人物如果知道这场事故，可能参与作证、组织互助或与 Josef 结怨。这些关系继续存在。
7. **历史路径**：工会可能利用多起真实案件形成政治议题，经过招募、谈判、选举或抗议推动制度改革，改革改变此后所有人的工伤索赔途径。

不是「父亲工伤 → 女儿辍学 → 激进+5」；每个转折都由**真实对象及未完成事务**组成。普通人生可以在任一步结束；不存在强行给每人安排英雄成长剧情。

### 3.3 人物之间的交互不能靠全局随机配对

相遇基础是**共处、社会纽带与现实事务**：家人/亲戚、学校班级、同事、邻里、军队单位、工会、咖啡馆、医院、迁徙旅途、会议、婚礼。

人物 A 向人物 B 发出请求时，先创建 PendingInteraction（邀请/求助/求婚/雇佣/借贷/告密/谈判）；B 有自己的可见信息与动机，可以答应、拒绝、拖延、欺骗、转告第三人或提出条件。系统不在 A 提交请求的同时强行写入 B 已经同意。

共同经历与认知必须有方向性：A 信任 B，不等于 B 信任 A；A 知道秘密，B 不一定知道。一个人物可能记错、误会或遗忘某段经历。日志不得把角色的**信念**当成客观事实。

### 3.4 一个组织拥有行动能力，不是成员列表

学校能够招生并颁发资格；企业能够雇佣、生产、借贷；工会有会费、成员、负责人、代表机制；军队有兵源、装备、补给和命令链；国家有法律、税、政权与强制权。

国家/组织的行动来源于职务权限、内部决策和可支配资源。一名玩家人物可以因进入某职位而影响 10 万人，但其影响必须通过具体机构执行，不能靠一个 `influence=100` 属性直接改写国家。

## 4. 宏观历史怎样真正落到每一个人身上

### 一套人口账，而不是两套并行游戏

全部人口按地区、年龄群、职业、家庭结构、社会身份等进行**聚合建模**；玩家人物、重要 NPC、历史人物是从中展开的具名个体，拥有持久身份和独立社会记录。

宏观人口中的士兵被具名后，原群体人数必须减少一人；战争中这名士兵伤亡时，宏观汇总不能再将他死亡一次。一个具名工人的工资不能在个体和宏观企业账上支出两次。

### 战争必须是真实的因果网络

战争由政治/军事组织的项目、联盟、补给、军队和地区控制结算；影响兵员征召、城市粮食、工作岗位、学校、交通、疾病、难民、家庭收入、家庭成员的去留与政治态度。具名人物能够通过职务、资源、情报、组织或技术干预战争过程。重大历史事件（战争、革命、金融危机）不是给每个角色各抽一次「受影响」卡片。

真实 20 世纪的暴行、迫害和战争伤亡可成为世界风险和历史事实，并保持史实/架空史明确区分；无需追求血腥文字或把任何民族/群体预设为天然有罪。

## 5. 1900 年真实地球与历史人物

- **1900 开局档案：** 国家、边界、主要聚落、政治制度、人口及社会阶层、经济结构、交通、技术、已有战争、具名历史人物；每项基于史料/数据，并记录来源与确定性等级。
- **真实资料的身份：** 1900 年以前的既成历史属于 baseline；1900 年以后的史实是候选历史参考，不是强制必须发生的事件。比如某个重要人物出生需要其父母仍然活着且出生条件可成立；历史可偏离。
- **历史人物的精度：** 常出场且具有真实影响的人使用完整模拟；大量历史名录先做索引与生涯时间窗，只有与现行世界相容时激活。不能把 28k 目录等同于 28k 个活跃智能体。
- **历史人物相遇：** 同一时间窗、能够合理到达的真实地点、共同社会网络或活动是条件。History Director 可以主动安排邀请、旅行、聚会和偶遇机会，但不得跨越物理条件凭空把已死者拖进酒馆。
- **历史回归：** 允许强 History Director 主动提出外交危机、经济冲击、社会运动、人物聚会等事件，创造历史轨迹重新接近现实的机会；但事后必须由人口、制度、组织和人物行为产生后果。干预来源必须可追溯。

## 6. 超常祝愿是社会史的一部分，不是额外小游戏

玩家愿望可能是普通期待、诅咒、超常能力或“自带系统”。出生时 LLM 深度理解其**语义**、可观察表现、限制、适用对象、消耗、失败条件、成长可能、公共后果和社会可见性。原文永久保存。

示例：「能识破故意谎言，但每次会失去一段珍贵记忆。」

- **真相：** 引擎记录事实、说话者主观相信什么、说出的命题、故意误导意图以及是否可感知；诚实的错误不等于撒谎。
- **发动：** 有具体对话及命题，能力符合观察距离/条件；从合法可用的记忆中选择代价对象并记录遗忘，不凭空删去世界事实。
- **效果：** 角色获得“该人这句话是故意欺骗”的个人知识，不必直接获得全部客观事实；其他角色并不自动得知。
- **历史影响：** 能力可能改变家庭关系、求职、情报工作和政治谈判，进而引发真实的制度和战争后果。

超常能力稀少的含义是**世界中实际拥有可超越现实规律效果的人数稀少**，并非每人都必然实现愿望；如果大量用户提出神级能力，由出生编译解释为潜能、成本很高的受限能力、普通期望或需时代条件激活的异常，而非为了“平衡”偷偷将愿望改成另一个东西。玩家能够在出生前看到可理解的编译摘要；隐藏的是未来人生，不是欺骗性改写祝愿。

## 7. AI 设计：让 LLM 创造机制与潜力，不拿它当随机日志润色器

### 7.1 出生：深度推演但不预定命运

在出生时读取该年份/地区的可验证事实、家庭和父母、社会政策、时代科技、孩子条件及祝愿。LLM 多角度生成**若干可能人生假设**，识别角色潜能、内在冲突、长期动机和可能遇到的障碍，将其编译为可执行条件规则、个人策略与可用能力。隐藏预演不直接写进世界时间表，也不提供给用户剧透。

某个角色可能希望成为医生，但从未就读学校；另一个人可能通过战争成为护士、政治活动家甚至死亡。出生时没有人可以提前决定这件事。

### 7.2 运行期：三类调用，不是人均固定调用

**创作调用**：世界出现全新技术、制度、社会冲突或内容缺口时，生成可复用的事件族/职业/组织行为，并自动编译发布。

**重规划调用**：人物目标破产、人格遭受重大转变或面对特殊复杂互动时，修订未来行为策略，不追溯修改过去。优先级不能只看权力和知名度，普通玩家人物也有预算与公平性保障。

**强导演调用**：主动塑造历史机会与外部冲击，改变当前可执行的社会环境。干预是新增事实、规则或事件来源，不是直接覆写已有事实。

普通行为、社会接触、疾病过程、出生死亡、经济交换和日志默认都由代码执行；死亡后可调用一次 LLM 根据真实生平总结，不得编造经历。

### 7.3 大规模 LLM 内容工厂：内容单位是机制族，不是句子

开发期批量建立**相互连接的内容族**（例如疾病治疗、学徒制、家庭债务、移民、战争征召、政治秘密、劳工运动、恋爱与婚姻、灾难救助、殖民/民族冲突、跨代遗产）。每族包含状态入口、参与角色、行为、相反回应、机构/资源条件、长期进程、失败和延迟后果、历史年代约束与可复用规则。

LLM 输出后进行格式编译、引用绑定、资源守恒、安全与效果检查、年代/区域检查、规则重复检测、合法状态迁移测试。正式世界的事件允许在**全部自动审核通过后无人工确认上线**。新规则注册后给未来事件使用；过去已发生事件仍按当时版本解释。

### 7.4 用户可见日志

只渲染**事实**，并区分传闻和角色的错误认知。普通经历使用内容模板，关键事件可有多角色对白/叙述片段，但不必须靠 LLM 为每件事写散文。重要的是同一件事可由多位当事人的不同认知与利益看到不同侧面，且都能追溯到同一条权威事件。

## 8. 如何自然地产生内容密度

必须由**社会活动场所**带来接触机会。七千多座城市中的 20k 具名人物即使分布不均，也不能只靠同城随机配对。世界还包含聚合普通人口；学校、工厂、军营、社区、教会、港口、医院、政府机构根据本地人口与需求生成可重复使用的社会结构。在需要时从人口单元激活有稳定身份的 NPC；一旦与具名人物形成重要关系便永久保留，而不是每次互动重新制造朋友。

有些人物的一生只有一段婚姻、几个亲密朋友和一份长工；这种生活仍应有明确的家庭、经济、疾病和社会历史，而不是靠导演强行让每个角色经历三次谋杀与两场革命。

## 9. 玩法内容覆盖矩阵（不是机械刷数量）

| 领域 | 必须具备的实际模拟互动 | 必须关联的宏观机制 |
|---|---|---|
| 婴幼儿 | 监护、营养、疾病、失亲、收养、家庭资源分配 | 人口、医疗、社会救济 |
| 少年 | 学校、师生、同伴、学徒、家庭劳动、教育限制 | 教育制度、阶层、地区经济 |
| 成年 | 雇佣、晋升、失业、创业、爱情、婚姻、育儿 | 产业、组织、财产和法律 |
| 老年 | 健康恶化、照护、退休、继承、遗言与关系终结 | 人口、养老制度、家庭财富 |
| 社会交往 | 介绍、邀请、请求、承诺、合作、误解、欺骗与背叛 | 地域、传播、机构、信息 |
| 政治 | 加入组织、招募、筹款、竞选、镇压、谈判、政变 | 政权、法制、税收、国界 |
| 军事 | 征召、服役、战伤、逃亡、情报、补给、复员 | 国家战争、工业、人口 |
| 历史与科技 | 发现、实验、机构采纳、制度阻力、社会扩散 | 技术、贸易、生产与文化 |
| 异常能力 | 条件发动、代价、泄露、被利用或被追捕 | 信息、宗教、政治、军事 |

**内容审计的单位是「可触发的机制组合与新后果」**，不是 `event_count`。事件定义 10,000 条也可能只有 30 条真能触发；反之 200 个机制族可以组合出大量各不相同的人生。

## 10. 例子：三条相交而非按剧本播放的命运

（完全构造的用于设计评审的例子）

- 玩家 A：1900 年出生在维也纳的 Anna，听谎但失忆。父亲工伤后她可能被迫中断学校；也可能通过老师获得资助。关键不是哪条情节更好，而是**母亲收入、校方制度、教师存在、个人性格和愿望代价**真的参与了结果。
- 玩家 B：1902 年在另一城市出生的 Karl，后来进入司法机构。他可以被指派处理工伤纠纷，和 Anna 的家庭或工会形成跨年关系。若 Karl 早亡或换职，整个链条可转向另一位具名人员，不要把他拉回固定剧情。
- 历史人物 C：某一真实人物在当时的城市和政治圈内活动；导演可以有意组织一次讲座、聚会、偶遇以创造联系。当代史实不保证其一定参加，也不保证人物随后必然完成历史教科书的行动。

如果 Anna 所在的工会在法律改革中发挥了作用，未来很多普通居民的工伤和教育机会都改变。这不是将 Anna 的 `fame` 加 100，而是让法律与行政机构执行新的规则。

## 11. 世界终局与代际体验

终局由真实的文明级变革、灾难或时代转折触发，可结束当前纪元并归档；不强制 2050 AI 叛乱等预设剧情。测试中需要有**最大模拟时长安全截断**，但它不是故事情节。

人物死亡后保留后代关系，允许继续观察后代及出生新生命。新生儿必须出生在当前或新世界的现实家庭里；不能通过账户选择任意富豪或历史人物做父母。历史档案永不因世界结束而变成废数据。

## 12. 成品应该是什么感受

玩家看到的不是一百条「今天努力工作」「关系+3」；他看到一段由真实人物、制度、工作、家庭和偶然机会形成的生活。他可以看见某个朋友几年后变成敌人，某次意外没有宏大意义，也可以追溯一项法律为什么改变了孩子的生活。世界继续残酷地前进，不保证公正，也不刻意讨好玩家。

# 世界人生 — 模拟引擎、LLM 与万人规模技术设计 v1.0

**本文件是提议的工程架构，不是既有仓库的代码审计。** 现有仓库 `/home/rust1/projects/world-simulator` 未挂载在当前运行环境；我们只能根据 Codex 的报告确定它*声称*拥有若干机制，不能证明它的真实性或质量。

## 1. 最重要的架构决定：一个可裁决的世界，两个精度层，两个内容入口

不建议从头引入第二个“AI 世界状态”或多个互相抢数据库写权限的模拟器。唯一权威状态由 World Runtime 管理；宏观人口/经济结算与具名人物详细行为是**同一世界两种精度**，通过守恒账本连接。

两种内容入口：

1. **机制内容**：可执行的行动、制度、场所和事件族，来自预置参考机制及 LLM 生成内容，通过版本化 DSL/规则 API 执行。
2. **个人出生契约**：LLM 深度理解具体孩子与祝愿生成的潜质、条件式策略、特殊能力，针对人物生效；它只能使用相同的世界行为与结算机制。

History Director 是第三种**提案来源**，不是另一个拥有真实历史的世界引擎。普通 LLM 决策和 Director 都只提交有条件、限定作用范围、可追溯的世界变更提案。

## 2. 明确数据模型及不变量

### 2.1 主要实体及字段

```text
World       {id, calendar, seed, time_policy, current_date, epoch, ruleset_version,
             director_policy, baseline_source_set, status}
Person      {id, world_id, born_at, died_at?, name, sex_and_body, location_id,
             household_id?, guardian_ids[], life_program_version, health,
             dispositions, commitments[], belief_ids[], roles[], provenance}
PopulationCell {id, region, cohort, status_class, job_class, household_class,
                aggregate_count, vital_rates, flows, economy_links}
Household   {id, residence_id, members[], guardianships[], income_accounts,
             expense_obligations, assets, liabilities, sharing_rules}
Place       {id, geo_location, kind, capacity, ownership, offered_actions[],
             institution_id?, availability_calendar}
Relation    {id, a, b, relation_kind, start, end?, commitments, shared_history_ids[],
             a_to_b_beliefs, b_to_a_beliefs}
Organization{id, kind, members, positions, authority_rules, funds, property,
             processes, projects, geographic_scope, decision_rules}
Position    {id, holder_person, org, entitlement, obligation, authority, start, end?}
Project     {id, owner, objective, participants, resources, state, stage,
             deadline?, blockers[], next_actions[], audit_history[]}
Interaction {id, initiator, counterparties, proposal, negotiation_state,
             expirations, knowledge_visibility, linked_project}
Knowledge   {id, holder, proposition, confidence, source, observed_at,
             expiration?, visibility, belief_or_verified_fact}
HistoricalEvent {id, world_date, actual_fact_refs, actor_ids, place_ids,
             action_id, causes[], changed_entities[], generation_provenance,
             severity, audience, chronicle_type}
RuleDef     {id, version, trigger_keys[], role_queries, guards[], proposals[],
             actions[], followups[], cooldown, provenance, effective_from, status}
DirectorProposal {id, generated_at, depends_on, proposed_for_date,
                  claims, scope, intervention_kind, cost, outcome, audit}
```

`Person` 的字段不必全部存在同一数据库表；这是领域契约，不是建议一张巨型 JSON 表。高频列式状态和稀疏关系/历史可分表。**任何对象引用都必须用稳定 ID，不用日志文字查找人物身份。**

### 2.2 必须永远成立的不变量

1. **人口守恒：** 聚合人口 + 从其中展开的具名人物 = 实际人口；人口流入/出生/死亡/迁移都有对应账本；展开 NPC 不可凭空制造人数。
2. **钱/物资守恒：** 实际财富与货物交易有支付方和接收方；工资、救济、军需和补贴不能无来源增加。宏观生产/税收/资产估值可以在明确定义的模型下改变总量。
3. **唯一历史：** 同一世界同一事件只能结算一次，采用幂等键；历史一旦提交不可追溯改写。
4. **时间因果：** 无法在死后参加真实谈判；不能从未来知悉未发生的事实；Director 不能把日期推回到影响已提交事件的时间点。
5. **独立意志：** 请求发起人与受邀者分别做决定，不能单方面让对方已签婚约、已被说服或已转移财产。
6. **信息隔离：** 人物知道的事实和世界真相分离；超常能力若突破认知边界要通过合法机制；玩家不可读取隐藏人生预演或别人的私人策略。
7. **年龄与身体：** 婴儿需要监护，伤残影响具体能力，死亡是终止大部分普通行为的状态（特殊复活/鬼魂另有世界机制）。
8. **规则版本：** 新事件不能改变已有历史事务在原版本下发生的事实；未完成 Project 的规则升级应按迁移策略处理。

## 3. 精确说明人与社会怎样共同结算

### 3.1 从聚合人口中生成真实 NPC

以某地区 `PopulationCell` 中的青年工人 8,000 人为例，工厂雇佣名单可同时引用：`7,995 名匿名聚合人员 + 5 名具名人物`。当某普通工人成为玩家人物的关键朋友，采用一次 `materialize` 事务：原 cell 减一、创建唯一 Person 和合法的家庭/就业/人口来源引用、写入 provenance。之后他永久具名，不因玩家不在线又被自动“合并回”人口并删除关系。

玩家创建的孩子则走出生账本：若宏观出生人数已经批量结算，从该批新生儿库存中提取一个并提升身份；否则出生事件同时增加真实人口与 Person，不可在两个系统各加一次。**历史人物预定出生**也遵守同一原则，且需双亲/地点/当前历史条件成立。

### 3.2 三种调度精度，不复制三套规则

**聚合结算：** 每月/季度，POP 年龄转移、婚育、死亡、迁徙、工资和消费、产业/战争产出；数十亿普通人口也可以使用地区/年龄/职业组合单元，而非逐人刷新。

**具名人物常规结算：** 按到期时间、生日、项目阶段、疾病风险、家庭变更、重要接触事件处理；人平时仍维持状态，但不每模拟天调用决策或 LLM。

**关键场景：** 两人重要谈判、法庭案件、军职抉择、婚姻重大分歧、政治阴谋、特殊能力使用，可进入精细多方事务，保存双方信息、行动及回应。

某次战争事件同时影响聚合 POP 的补给/死伤，及具名士兵的具体健康与社会关系，最后通过账本对账，不能分开独立抽伤亡。

### 3.3 人与人相遇：从地点与关系构建候选集合

关系网络应当来自家庭、场所与事务，而非全世界随机连边。以 `place_presence`（学校班级/工作班次/医院/军营/公共会议）、`membership`、`relationship`、`project_participants` 和 `travel_itinerary` 索引提供候选；优先共享近邻和真实关联。若另一人只是名字出现在历史目录里、时间地点不符合，他不会自动进入候选。

互动流程：

```text
社会场所/事务给出候选接触人
  → 依据双方所在地、时间、权限、认知生成可以提出的行为
  → 发起人选择/提出请求（程序常规行为或 LLM 特殊策略）
  → 写 PendingInteraction
  → 接收人收到请求，根据自己的认知和意愿答复或反提案
  → 共识/拒绝/拖延/冲突产生 Outcome
  → 已经提交的改变成为双方关系、家庭、组织和历史的一部分
```

长期相识不需要每次重新生成一次聊天；日常维护关系可以按共同生活时长和关键事件更新。

## 4. 统一规则执行机制：不要只做 `+trait` 的假引擎

建议采用 **已知实体 + 有限类型的状态效果 + 可组合事务/过程 + 触发规则**。可以借鉴 Cataclysm:DDA EOC 的周期/事件驱动与作用域、Wildermyth 的角色约束/历史改变、CK3 的 on_action/scope、FreeSO 的行为脚本/交互队列，但不直接照抄任何一个世界状态模型。

### 4.1 可执行内容至少要支持六类语义

- `query`：带索引的实体查询、关系图查询、位置时间窗、群体/角色过滤。
- `guard`：状态、知识、组织权限、资源、社会规则、历史年代与冷却条件。
- `offer/action`：人或组织可以尝试做什么，谁需要回应。
- `process`：持续申请、就业、科研、贸易、战线、治疗、组织计划，可中止和重排。
- `effect`：资源转移、伤害与恢复、建立/取消关系、赋予职位、修改组织、启动新 Project、对人口施加政策或地区过程。
- `followup/history`：延迟事件、版本化规则、个人记忆、完整因果链接与可读历史。

不限固定十个原语，但新效果必须有清晰的资源与权限边界。不能把一个全局任意 `set` 暴露给 LLM。

### 4.2 可供实际编译的事件例子

```yaml
id: labor.injury_claim
version: 3
on: employment.injury_confirmed
scope: workplace
roles:
  worker: {ref: event.worker}
  employer: {ref: worker.employment.org}
  doctor: {query: {has_role: licensed_physician, place: worker.current_region}, optional: true}
  union: {query: {member_group_contains: worker, kind: labor_union}, optional: true}
requires:
  - {op: alive, ref: worker}
  - {op: existing_contract, between: [worker, employer]}
offers:
  worker:
    - submit_compensation_claim
    - waive_claim
  employer:
    - offer_settlement
    - contest_claim
    - request_medical_assessment
process:
  create: legal_claim
  parties: [worker, employer]
  target_jurisdiction: {ref: worker.workplace.jurisdiction}
  deadline_policy: jurisdiction_labor_claim_limit
outcomes:
  agreement: [transfer_existing_compensation, record_settlement]
  contested: [schedule_hearing, update_participants_beliefs]
  no_claim: [close_case]

# 注：示例契约，尚非现有引擎实际支持的 YAML。
```

这里的 `doctor` 只能从存在的、具资格的人中匹配。`schedule_hearing` 创建一件真实未来事务，不能直接宣布申请人赢官司。若地区法律没有赔偿途径，事件从一开始就不应提供不合法的司法选项。

### 4.3 规则发布管线与索引

`Draft → Schema Parse → Static Type Check → Scoped Query Check → Guard/Effect Check → Invariant Check → Synthetic Fixture → Staged Active → Active`。这是**自动发布**，不需要人工审核。`Staged Active` 可只表示先编译并原子替换指针，而非人工批准阶段。

基于 `trigger_key → rule_ids`、地区/年代/职务/组织类型/人口标签二级索引匹配候选，之后才做昂贵条件检查。禁止每模拟日 `N 人 × 全部 R 条规则` 双重扫描。新事件入库之后在索引层增量生效，支持撤销新版本/隔离异常规则，不删已提交事实。

动态内容缺口应从世界事实驱动：新技术出现、组织人数激增、某类事务失败率升高、事件匹配覆盖极低、重要历史变更、玩家祝愿引入新可观察行为。避免无目的地每隔一分钟凭空生成 1,000 个随机事件。

## 5. 深度出生编译 Life Contract

### 输入

`WorldSnapshotRef`（当前日期、地区法律、家庭与监护、技术、社会环境、宏观历史、已存在的重要人物及组织）+ 用户创建信息 + 原始祝愿。

### 生成成果

1. **语义解释与可见摘要**：这句祝愿到底是美好期望、实际超常能力、讽刺/诅咒、私有任务系统还是矛盾愿望；允许多种可能性，但提交前必须给出明确实现版本。
2. **出生事实**：身体与先天条件、家庭归属、出生地点和时间；由 World Runtime 最终认定。
3. **私人 Life Program**：目标候选、价值倾向、长期兴趣、学习/交往策略、对特定压力的条件式反应；规则与人物历史可结合。
4. **隐藏 Life Forecast**：若干不同世界条件下可能发生的轨迹与失败方式，只作预测和个人未来反思，**不是事件时间表**。
5. **Wish Capability Contract**：触发、作用对象、范围、代价、冷却、认知权限、执行效果、成长/失效/被压制机制。
6. **Provenance**：模型、规则版本、上下文摘要哈希、编译日期、用户输入哈希、编译校验结果。

### 原子出生事务

先异步编译后进入 birth-reservation 队列；在**实际提交**时重新确认父母仍存在、监护条件、当前世界日期和人口账本。若父母已死/迁居，应重新选择合法家庭并必要时重编出生上下文，不可拿过期 LLM 结果强行写入当前世界。用户提交出生到孩子正式出生可能存在排队延迟，但不能直接回退为无 LLM 的普通模板出生。

## 6. LLM 角色与权限边界（可操作版本）

| 角色 | 何时调用 | 可提交 | 不可以 |
|---|---|---|---|
| Birth Simulator | 每个玩家出生 | 祝愿解释、生命预演、个人规则 | 确定几十年后事实；凭空抢夺他人身份 |
| Life Replanner | 战争失亲、失业、改信仰、计划不可行等显著转折 | 未来目标/行为策略新版本 | 修改已经发生的经历 |
| Conflict Deliberator | 稀有复杂互动、重要政治决策、异常能力使用策略 | 双方要提出的行动、意图、陈述 | 直接宣称另一方已同意或已死亡 |
| Content Author | 发现内容缺口和新社会现象 | 编译用事件族、触发、角色、行为、流程定义 | 向生产 DB 发 SQL；执行任意代码 |
| Historical Director | 重大世界变化与导演周期 | 外生冲击、主动邀约、政治危机、罕见历史巧合 | 清除之前事实；强行规定战争结局 |
| Life Summarizer | 人物死亡归档后 | 事实引用的最终生平与祝愿对照 | 编造英雄事迹、感情关系或历史人物会面 |

### 强导演的特殊权力

可创建**真正的新原因**：例如跨国外交活动、事故/灾害源、经济供需冲击、政治宣传机会、科学发现的机遇、相遇的邀请链与交通安排。不用要求它完全被既有社会过程被动触发。但仍必须：限定影响范围、验证前提、生成来源审计、成本与强度预算、预定将来生效、执行后遵守同一物理和社会过程。干预可偏向历史回归，却不能直接提交 `1914 年必须爆发一战`。

### 运行期新机制扩展的两种边界

- **规则组合扩展：** 用已支持的脚本结构、事务和效果自动生成新内容，通过编译测试后即刻发布。这是常态。
- **底层执行器扩展：** 真正新型数据结构/物理规律/结算器需要更改生产代码；可交给 Coding Agent 生成补丁、在隔离环境进行构建和迁移测试，再进入独立部署流程。**不允许直播世界自动运行未经隔离审核的任意生成代码。** 这条与“LLM 事件自动发布”并不冲突。

### 预算与公平

世界级 token budget 按 `birth / personal_replan / world_content / director / death_summary` 分队列，支持 token 上限、优先级、缓存与重试。强制限制每人/每世界同一时间窗的深度调用次数，但为无名普通玩家保留最低可用资源，不让 LLM 只偏爱著名人物或富豪。相同知识与内容族缓存复用，但个人预演不能简单复制他人的整段未来。

## 7. 30/60 秒一年：真正的计算契约

### 7.1 不是模拟中每天真实睡 82 毫秒

内部世界时间用模拟 `day_index` 或精确日期、离散事件队列推进。**真实墙钟只控制对外可见的目标世界速度**。某个模拟日没有事件可以直接跳过，重要事件能按日期排序，宏观人口可按月/季批量运算。不要每“世界日”逐角色扫描。

- 测试倍率：30 秒/年，月约 2.5 秒；60 秒/年，月约 5 秒。
- 离线跑数：尽可能快跑完整世纪；保留同样规则和同样历史事件产物，不与网页渲染绑定。
- 生产：倍率从独立的 `TimePolicy` 表读取，可调；不应该在法律、教育、战争或个人记忆代码中直接出现 30 或 60。
- UI：每几秒拉取新章节，用户可以回看之前的日志；历史阅读进度独立于当前世界时间。

### 7.2 以 20k/40k 具名人物计算热点

假设每名具名人物每模拟月平均一次基础状态触发：

- 20k 人 × 12 月 / 30 秒 ≈ **8,000 次人物月激活/秒**。
- 40k 人 × 12 月 / 30 秒 ≈ **16,000 次人物月激活/秒**。
- 如果每名人物每模拟年产出一条永久历史记录，20k 人的 30 秒/年相当于 **667 条历史记录/秒**；一天最多 **5,760 万条**，每条平均 500 B 是 **28.8 GB 原始数据/天**，还不含索引/备份。这不是建议的记录密度，而是上界警告。

因此**常规状态更新不写成逐条日志**；按脏集合批量落库，常规行为汇总为里程碑/持续时间，在未影响未来的操作上不制造永久故事。真正的出生、死亡、婚姻、迁徙、组织更迭、创伤、法律改变等仍要可追溯。存储预算用“每 100 模拟年/每世界”而不是只看每真实天；如有大量赛季归档，仍需冷存储策略。

### 7.3 VPS 预算

用户提供服务器：6 共享 vCPU、13 GB RAM、113 GB NVMe，长期平均 CPU ≤30% 总机（约 1.8 个 vCPU 等效），24 小时满载仅允许短时。**这是一个运维约束，不应宣称全系统能稳定占 1 核。**

- 权威模拟器尽可能采用单写者，内存增量索引，热点状态缓存，少写数据库；多线程主要用于离线预处理与旁路任务。
- 浏览器/公开章节与静态资源由 CDN 缓存，个人记录走鉴权 API；轮询最新章节，不要求 WebSocket。
- LLM 推理使用外部 API，设限流、并发池、超时与熔断。异步任务带 `depends_on_state_ids + revision`，提交前检查对象版本，避免世界前进导致过期计划偷改事实。
- 后台归档、索引维护、规则编译分散执行，不与推进世界的计算尖峰叠加。
- 需要外部备份；同一台 VPS 的复制不是灾备。

### 7.4 已进行但有限的实验

当前会话运行了已有 `sim_kernel_load_probe.py` 合成内存调度探针：20k 人、约 14.7 万有向关系、8k 规则、1 模拟年，约 1.13 秒墙钟；40k 人、约 29.4 万有向关系，同规则约 2.91 秒。环境为当前容器的 Python 单进程；仅索引、定时触发、简化关系与筛选，**没有数据库、真实人际因果、战事、LLM 或异地存储**，不能用这些秒数推导实际 VPS 容量。合成数据里每个人每月更新一次已经包含了 12 次左右激活。实验源码附在交付包，可重跑。

## 8. 人口规模与快时间的人物供给（不可回避的产品数学）

在 30 秒/年下，100 年世界只存在 **50 分钟**，70 年人生约 **35 分钟**，现实一天跨越 **2,880 个游戏年**。即使模拟可以处理 40k 名具名人物，也不表示有足够多的真实玩家持续补充孩子。

假设想长期维持 10k 个**同时存活的玩家角色**，且平均存活 70 年，则需要每模拟年 10,000/70≈143 个新玩家孩子，按 30 秒/年即 **约 17,143 次真实注册出生/小时**。60 秒/年仍约 **8,571 次/小时**。死亡率及实际加入时段变化会使数字波动。

建议将 **10k+ 玩家注册人物/一世界历史累计** 与 **10k+ 同时存活玩家人物**列为两个不同容量指标。用户没有要求持续 24h 同时活着的 10k 账户角色，因此不应为了名义人数偷偷制造不死小人或免费补人。若未来确实要求后者，需改变正式世界速度、赛季加入结构或运营规则；不是单靠优化引擎就能实现。

测试阶段完全可以选 300、1,000、3,000 名具名人物 + 完整 POP、全机制跑 100 年；**不要删掉机制**，只改变数据密度、角色实例化规模、地图关注区域和目标时钟。

## 9. LLM 数量级成本（不得口头说“可忽略”）

举例，单名出生编译假设 8,000 输入 tokens + 2,000 输出 tokens（**容量假设，不是推荐 prompt 大小**）：

- 10,000 个注册出生 ≈ 8,000 万输入 + 2,000 万输出 = **1 亿 tokens**，尚未算重试和重规划。
- 若人均 70 模拟年固定触发一次深度规划，在 20k 同时存活、30 秒/年下是每模拟年 20k 次 → **每天 5,760 万次调用**，根本不适合。
- 只有「按事件重要性与个人预算触发」+「内容族共享复用」+「离线批量编译」才能控制调用量。出生编译不可被无 LLM 规则替代；如调用量不足，新增出生进入待处理队列，并明确前端告知排队，世界不暂停。

运营成本公式：`总价 = 输入总 tokens × 输入单价 + 输出总 tokens × 输出单价 + 重试 + 基础设施`。模型和接入商的当前价格、限流、缓存折扣需要实际测量，不能写死估价。

## 10. 权威世界单写者、事件日志与档案

### 10.1 内存执行与写入

1. 从时间队列取到期宏观批处理、项目阶段、人物接触、能力冷却、战争/死亡事件。
2. 构造只读决策快照，产生动作提案（本地规则优先、少数任务异步 LLM）。
3. 由权威 Resolution 依次验证前提和资源；涉及多个实体的操作原子执行。
4. 写入状态日志（能恢复），按历史显著性额外写 ChronicleEvent（给人看）。
5. 更新二级索引、下游事件订阅、下一次到期任务。
6. 定期生成状态 Snapshot，保留世界 seed、规则版本、LLM 已提交输出以支持回放。

`State Journal` 与 `Human Chronicle` 必须区分：不是每笔微小流转都要成为人生记录，也不能仅靠精美日志恢复世界状态。建议 DB 初期以 PostgreSQL 为中心，压缩归档与不可变大日志迁移到廉价对象存储；实际结构依据已有仓库实现选择，避免推倒重写。

### 10.2 多人一致性与内容即时发布

所有角色同世界数据库、同一世界时间、同一权威提交者。新增 LLM Rule 在 `effective_from >= next_safe_boundary` 时生效，不溯及过去。跨人事务采用对象版本与幂等键，不能简单使用 `global_revision`，否则无关城市的一次交易也会废掉大批 AI 计划。规则索引按版本热更新，正在执行的事务可继续使用其锁定版本或显式迁移。

### 10.3 可缓存的公共页面

公共章节/世界地图状态使用不可变 URL 例如 `/public/world/<id>/chapter/<n>.json`；`/latest` 短缓存/条件 GET；人物私人记忆、出生草稿和预演结果绝不能进入公共缓存。Cloudflare 对 JSON 需要显式适配 Cache Rules，不可只靠 `immutable` 假定所有 JSON 已边缘缓存。

## 11. 历史事实、伪造内容及安全

- 1900 baseline 的来源和确定度必须跟随资料项；历史人物的行踪不详时允许虚构合理补全，但要以“游戏架空内容”标注，不是史实。
- 新剧情和规则数据标识生成模型与生成时间，不能把虚构的历史人物语录写成真实引文。
- 1900–2050 可能涉及真实屠杀、殖民暴行、战争与仇恨政治；模拟不能把民族、宗教或现实受害群体天然设为负面属性，也不把残酷历史改成娱乐化虐杀日志。
- 自由祝愿和事件文本是非可信输入；严格结构化输出解析、作用域限制、无任意 SQL/文件/网络/代码执行。公开文本有平台内容治理，不能任由其他玩家通过输入注入系统指令。

## 12. 关键能力的验收方式（自动化而非让玩家不停手动测）

**合格不是“225 项测试通过”，而是完整因果运行。**

A. 父亲工伤后：若企业赔偿成功，孩子可能继续读书；若失败且储蓄不足，家庭真实面临工作/借贷压力。同一事件驱动家庭、就业、学校、法院与组织，不硬编码 Anna 的结果。

B. 两名真实玩家人物：同校/同工厂/同军队的接触几率高于无关联随机人物；对同一请求双方可以作不同选择，形成长期记忆和后续事务。

C. 制度从无到有：通过几十年真实组织行动产生工伤法，法条生效后新的受伤事件自动出现更多法定手段；删除 LLM 仍能执行。

D. 超常能力：区分故意谎言和真诚误信，消耗真实记忆，关系改变；使用同一事实事件跨人可查询不同主观认知。

E. 强导演：可以成功引入合理的外生冲击/历史人物聚会机会，实际人物可拒绝，所有干预记录 provenance，不能改过去。

F. 灾难战争：宏观人口伤亡与具名人伤亡完全对齐，不会一个士兵死两次；新的难民迁徙会真实改变学校、工作、医院和两地关系网络。

G. 长期历史：同一随机种子 + 相同外部 LLM 生成结果 + 相同规则版本应能复现；快进、保存/恢复、断点继续与正常步进的状态哈希一致。

H. 性能：分别记录 300/3k/20k/40k 具名人物、不同社会网络密度、不同事件库规模下 CPU 平均/峰值、DB 写入、内存、历史磁盘增长、LLM tokens；目标按现有 VPS 实际预算确定，不能用合成探针声称已达标。

## 13. 执行顺序（现有仓库增量升级）

1. **先读取真实源码：** 人物生命周期、家庭/POP 结算、关系存储、组织/战争、事件执行器、LLM 接口、事务/历史、Web。输出保留/需补/必须重构的判定和证据路径。
2. **稳定人口守恒和跨人事务：** 因为这两处不成立，之后新增任何事件都会放大错误。
3. **成熟的规则索引、作用域、多角色匹配与延迟执行：** 先把底座统一，再让 LLM 写事件。
4. **Birth Contract + 特殊祝愿编译：** 必须真实进入现有人口、家庭、能力、人物认知模型。
5. **历史与社会内容生产流水线：** 开发期大量生成实用事件族，运行期有条件自动扩展。
6. **宏观历史与具名角色双向反馈、强 Director：** 不断改写后续机会而非播放史实。
7. **完整人生观测与运行优化：** 当前三栏 UI 只读权威日志，持续增强像素纸娃娃、人物履历与回放。

不再先做另一个空壳 Demo，但**必须在同一项目里用自动化因果运行数据证明各机制确实接上**。

# 世界人生 — 可执行机制定义与具体因果案例

这是对 `01/02` 的进一步补充：**把机制写成输入、选择、公式、状态迁移与多方后果**，减少 Coding Agent 自行猜测「人物到底如何生活」的空间。所有数值案例均是**演算示例而非真实历史统计**。正式数值必须由 1900 年历史/地区资料校准；公式为建议实现语义，允许在源码审计后保留更成熟的现有实现。

## 1. 每个模拟月究竟计算什么？

**不要每个人每天主动触发一次随机行为。** 单个 30 秒/年的世界，30 秒代表 12 个月；各月约 2.5 秒墙钟时预算。真正处理以日期优先队列为基础，可在月内有具体日的重大事件。

按领域依赖组织一个模拟结算周期（需要明确事务优先级）：

1. 读取已提交的战争、气候、疫情、地方法律、物价、工业能力、交通可用性。
2. 组织/工厂/医院/学校本月公布实际容量：多少职位、工资、病床、学额、粮食、药品、经费可用。
3. 结算人口层的资源生产/消费/供需、必要的年龄/出生/死亡风险候选（不在此对具名人物重复死亡结算）。
4. 提取到期的具名事务：工资支付、申请结果、治疗进展、项目截止日、学校学期、军役、家庭迁徙、重大健康状态变化。
5. 角色或组织按实际需求向存在的对象发出提议；对方独立回复，资源/权限/在场条件经最终裁决。
6. 将真实后果原子写入权威状态，并发布 `on_birth/on_death/on_contract_changed/on_event_committed/...` 供内容匹配。
7. 以事件显著性产生可读历史里程碑，记录因果而不是每月流水账。

**精度不是固定的：** 户籍年龄/人口可以月结算、工资按发薪周期、学业按学期、军役战役按必要日期、政治运动按阶段。一个几个月没有事件的家庭无需强制制造微小戏剧。

## 2. 婴儿、家庭与养育：出生就能产生真正不同的命运

### 状态

`Household` 要有实际住房、现金、食物可及性、收入成员、支出/税/租、债务、监护人、照护负担与子女；`Child` 有营养、身体状况、受教育资格、对照护者的记忆及依赖。除突发死亡和遗弃等情境外，婴儿多数决策由监护者执行。

### 具体规则

- 新生儿食物/护理需求来自年龄及身体状态，由监护人的收入、可用时间和卫生条件满足；长期缺口改变疾病暴露和生存风险。
- 父母、其他亲属、孤儿院或社会救助机构的照护能力必须有实际人数/资金/容量；不能无限领养。
- 监护权与亲子关系不同：亲生父亲也可能失联，孩子的实际监护人是外祖母。
- 父母死亡触发遗产/债务、抚养安排、居住搬迁、照护可用性变化；**不**直接等于孩子获得“孤独+10”。孩子对死亡的理解会受年龄、同住经历与信息来源影响。

### 案例

一名父亲在军中死亡，家庭现金减少，但祖父母可能提供住房，国家可能有抚恤，母亲可能重新就业。另一名孩子没有亲属资源，家庭走向贫困。**战争与两段人生之间的差别来自家庭网络和制度**，不是骰出两个不同文本。

## 3. 疾病与死亡：少数可靠模型比“每年死亡概率”正确

### 3.1 竞争风险模型

按当前年龄、地区、性别/身体、年代等给定**基线死亡危险率** `λ_base`（单位：每模拟年），疾病、战场、饥饿、职业风险增加原因危险率。若某段时间 `Δt` 年内率近似恒定：

`P(death during Δt) = 1 - exp[-(λ_base + λ_disease + λ_war + λ_famine + λ_job) × Δt]`

抽到死亡后，按各原因危险率比例选择主要死因，再检查治疗、暴露程度与因果事件。若战争与流行病已由另一专门系统分摊伤亡，必须**从基线危险率里扣除/拆出相应来源**，避免两次计数。出生/死亡均必须与人口聚合账本对齐。

### 3.2 临床与社会后果

疾病是一个过程：暴露 → 潜伏/感染 → 临床影响 → 治疗/恢复/并发/死亡。它改变实际劳动、照护、学习、经济和传染风险；医院有可用医生、床位和药品；医学能力随历史技术变化。疾病日志应说明确切诊断存在不确定性时只是“被认为患病”。

### 3.3 参数校准

从 Human Mortality Database 等按国家/年代/年龄的来源校准可得地区，空白地区用不确定性更高的参数与附近社会条件推估并标注。不能简单把全球 1900 年人物的死亡率设为相同的 0.02，也不能保证玩家孩子长大。

## 4. 教育：入学是一种竞争与长期承诺

学校具有年龄/性别/地区/阶层在当时的资格制度、师资、学额、学费、学期、学术或职业课程。一个孩子能否升学由**两阶段行为**决定：

1. 家庭/本人是否申请、是否愿意支付、是否得到教师推荐、是否受政策限制；可同时存在其他生活目标。
2. 学校在截止时间根据资格和名额作招生决策，最后结算家庭现金、在读状态及课程；未入学不等于立即转为工人。

**示意演算**（虚构数字）：家庭月收入 60，必须开支 51，学费 14，剩余资金 9；学生申请奖学金 10，可用其他亲属捐助 5，则学费资金从不足变成可能满足。但是若当地制度禁止某种入学资格，即使有钱也不能立刻入学，除非特殊制度改变/学校另有名额。只有完成真实学业/考试才能拥有毕业资格。

老师是一个具名或可永久具名的人，可以因为过去课堂经历主动推荐，不应由事件刚出现时临时拼一个“慈祥教师”。

## 5. 雇佣与工厂：钱与工作必须有真实往来

**招聘来源**：企业某职位的计划岗位、工资预算、技术要求、地区劳动供给、工作条件。**求职者来源**：个人需要、技能、关系介绍、地点与交通、身份资格。两侧在符合条件后各自打分：企业看技能/用人成本/风险，工人看工资/工时/安全/未来计划/家庭义务。

达成真实雇佣合同：雇员、雇主、岗位、薪酬、日期、班次、资格、履约义务；工资从企业现金转入家庭/个人现金，不得空降。企业生产并卖出货物获得收入；如果连续亏损，就需要借贷、降薪、关闭岗位或破产，而不是永远有钱发薪。

**示意演算**：印刷厂本月收入 1,000，原料与维护 400，工资预算 430，税/贷款 110，剩余 60。Josef 受伤无法承担排字工作，企业若暂停他月薪 30，Josef 家庭月底少收 30；企业不应在停薪的同时再重复支付给他。后续赔偿若发生，从企业或保险账户真实划出。

## 6. 社会交往：不是每月 friendship += 1

### 6.1 真实接触机会

**接触候选集合：** 同住家庭、工作场所/班次、学校班级、同组织与共同项目、交通与同场活动。索引保证候选真实存在且有时间重叠。关系紧密的人可能在不同城市通过信件维系联系，但信息传播有延迟和费用。特殊导演聚会是新增**真实活动和邀请**，不是全局随机强配人物。

### 6.2 方向性的关系

关系至少区分 `trust`（相信说辞）、`affection`（情感）、`obligation`（承担义务）、`respect`（能力/道德评估）、`fear`（威胁感知）等**不同维度**；这只是支持行为判断的数值辅助，不是人格的完整语义。共同具体经历以事实 ID 存档，各人主观 `Knowledge` 与 `Interpretation` 可以不同。

### 6.3 具有回应的互动

A 请求 B 在诉讼中作证：A 有真实利益，B 可能有工作风险、对 A 的关系、对事实的记忆。B 可以拒绝或在压力下撒谎。此时世界中的法律制度决定证言如何被法院使用；A 的意图不能直接将 B 改成同意。B 有异能读心也不能凭空获得所有证据，需要合法的感知触发与代价。

## 7. 项目（Project）与组织：如何从小人物进入世界史

任何持续活动用有实际参与者的多阶段项目表示：

`准备 → 获取资格/人/资源 → 发起 → 争取回应 → 推进 → 成功/失败/撤回/改道 → 产生新事务`。

**政治改革案例：** 一群受工伤影响的工人先尝试找工会/律师，组织收集真实案件、招募、筹款、游说议会，反对组织可以说服工人退出、推动镇压或提出反方案。改革成功需要真实政治权力主体通过法律，而不是人物威望超过阈值。成功后法律向所有工伤争议提供不同的程序条件；即使原倡议者死亡，制度继续生效或被新的政权废止。

**组织内部机制：** 职位权力、投票/委任/军令规则、成员参与意愿、资源、对外联盟；普通匿名成员可按 POP 群体模型参与组织态度/罢工人数，重要领导和不同意见者则作为具名人物产生可追踪的选择。不要把普通成员忽略，亦无需每人调用 LLM 投一票。

## 8. 战争/流亡/历史人物：宏观冲击如何落入家庭

**战争前提**：国家或武装组织具有战斗单位、兵员来源、补给、工业、地理与政治目标；外交联盟、动员和政治组织决定军事行动可能性。战争不必须复刻 1914。

**召集**：特定地区年龄与职业的征召人群按当前法律选出，具名人物依据真实资格、地点和身份进入军队；抽象人口同步扣除兵员进入军队池。医务人员和难民也有真实迁移与劳动影响。

**战场**：军队承担损耗，具名士兵的具体受伤/死亡必须与单位整体战损对账。军队与地方食品/运力需求改变城市工厂、物价、家庭和医疗能力。战线变化后难民流向真实可达的地区，增加这些地区的住房、工作及医疗压力。

**真实历史人物**：以相关城市/时期/组织为行动窗口，已知史实与不确知补全有明确区别。1913 年维也纳咖啡馆可以由导演创建活动，但谁符合出行、地点、存活和社交条件需要裁决；不得为了名场面把不在城里的人硬塞到同一张桌子。

## 9. 异常能力与“系统流”怎样与普通规则共用执行器

以“识破故意谎言但损失记忆”为例：

```yaml
capability:
  id: discern_deception
  trigger: social.communication_received
  guards:
    - target_statement_is_observed
    - listener_conscious
    - remaining_usable_memories >= 1
  observations:
    detect: speaker_intends_to_mislead
    distinguish_honest_mistake: true
  costs:
    - remove_one_high_salience_personal_memory
    - create_private_health_stress
  outputs:
    - create_belief_about_speaker_statement
    - record_ability_activation
```

这是目标语义。关键不在 YAML，而在 runtime 能访问**说话者的当时意图与信念**，并有按条件消耗个人主观记忆的事务。如果引擎只有 `trust ±10`，这个能力根本不可表达。若超常能力凭空造出某种不支持的新资源/物理效果，要么编译出受限近似机制，要么走新的执行模块部署流程，不能凭一句模型断言就算实现。

“系统流”可以建成角色私有的 **RuleSet + Goal/Reward Generator**：在角色满足世界事实时发布私人任务和奖励；任务必须符合世界内可获得的技能、道具、权限和代价。系统不可以命令别的真人账户，也不可以直接把整个城市变成私人财产。

## 10. History Director 的强导演权究竟有多强

允许主动注入三类新因：

1. **外生冲击**：疫情输入、自然灾害、经济供需突变、突发事故等；影响必须按地区、传播/物流/资源机制结算。
2. **历史机会**：外交会议、知识交流、暗中赞助、组织宣传、战争借口、政治阴谋机会；事件为已有行为提供新可能，而不是代替当事人完成行动。
3. **有意识的相遇安排**：主动建立聚会与介绍路径，甚至支付组织者资源和让某人有参加理由；最终仍可能失约、拒绝、死亡或因战争改道。

每个 Director Proposal 带 `scope`、`effective_date`、`causal_inputs`、`novelty_or_reversion_goal`、`resource/strength_budget`、`probable_affected_population`、`provenance`。校验通过并提交后才是世界事实。Director 可以偏向某种著名历史场面，但其偏好不能成为绕过死亡、行程和资源的特权。

## 11. 内容工厂示例：不是生成 100 条“失业了”日志

**战时难民家庭内容族**应包含真实参与者：逃亡家庭、原居地政府/军队、边境管理、交通网络、收容社区、学校、雇主、医院、失散亲属。可执行行为：申请证件、雇佣交通、被阻拦、求亲友担保、加入救济、亲属搜寻；后果：资产损失、健康风险、收入变化、分离与重逢、当地劳动力/政治氛围改变。每项都绑定当时真实法律与移动条件。

LLM 可自动生成若干版本：不同国家、战争规模、家庭阶层、亲属条件等，但必须通过规则编译器确认角色能匹配、资源真的流转、结果回到现有社会机制。编译失败是**机制缺口**或内容缺陷，不应强行降低成一条漂亮日志。

## 12. 防止“明明写出系统了，游戏还是垃圾”的可解释性输出

每个具名人物的重大经历至少能回答五个具体问题：

- **发生了什么**（带时间/地点、真实参与者、实际动作、客观后果）；
- **为什么轮到这个人**（匹配到的学校、工厂、关系、家庭、军役/所在地点，不是“随机事件”）；
- **他当时想做什么**（目标、真实请求、认知、反应）；
- **其他人怎么回应**（谁有权说了算、拒绝/合作、利益冲突）；
- **后来变成了什么**（持续事务、关系、职位、法律、组织和未来事件资格的改变）。

这不是强制为所有小事写五段解释，而是引擎的因果记录必须能支持这样的追问。否则我们无法证明所谓“人生与历史相互影响”真实存在。

# 世界人生 — 参考项目研究、实际测量、工程迁移与验收

这不是让 Codex 去照着 README「研究一下」的任务清单，而是本轮**实际查到的代码/脚本特征**、适用范围、可复用边界与未完成的调查清单。引用日期：2026-10-31。代码与许可证状态可能随版本变化。

## 1. 具体项目怎么做，我们能借哪一部分

### A. 人生重开模拟器（Remake）——适合年龄内容，不适合多人世界核心

- 仓库：https://github.com/VickScarlet/remake
- **实际查看源码**：`packages/core/src/event.ts` （主分支，约 53 行）；其中 `check(event,state,profile)` 从 `@remake/data` 取得 `include/exclude/NoRandom`，通过 `@remake/condition` 筛选；`trigger(eventId, state, profile)` 应用 `LIF/AGE/CHR/INT/STR/MNY/SPR` 等状态效果，之后依次检查 `branch` 并递归触发后续事件。
- 可借：事件数据与代码分开、条件筛选、加权事件、分支执行、天赋与年龄阶段。
- 不能照搬：这套核心效果主要是单人物属性更改，不保存另一名实际存在人物的雇佣、亲属、承诺、社会认知与组织权限。我们的事件可以借其**内容管理与分支思想**，不能仅把数值效果换个名字就叫社会模拟。
- 直接复用代码？其部分代码与数据可以进一步查许可证；应对特定文件和依赖做法律检查，再定 copy/port/only-reference。

### B. Wildermyth ——目标选角、人物永久经历、场景驱动

- 数据格式：https://wildermyth.com/wiki/Data_Format_Overview
- Target Matching：https://wildermyth.com/wiki/Targets_and_Scoring_Guide
- Story Inputs/Outputs：https://wildermyth.com/wiki/Story_Inputs_and_Outputs
- 实际机制：事件指定 `hero`、`lover` 等角色；Required、Optional、Forbidden 角色与分数门槛；角色性格、关系、History、地点和公司历史影响可否成戏。`History` 可以永久添加/移除 `Aspects`，进而改变人物后续技能和事件资格。
- 可借：**先寻找实际参与者再发生故事**；历史记录不只是文本，还改变未来行为；系统要能解释为什么一个故事无法触发。
- 不能照搬：它的主要活动规模是队伍冒险，不适用于按同样精度逐秒更新 30k 位人物，也没有我们想要的近代人口与国家经济。
- 复用决策：取设计与字段语义，商业游戏内容/素材不直接复制。

### C. Cataclysm: Dark Days Ahead ——成熟可执行条件内容

- EOC 文档：https://docs.cataclysmdda.org/JSON/EFFECT_ON_CONDITION.html
- 实际机制：`ACTIVATION`、`RECURRING`、`EVENT`、`NPC_DEATH` 等类型；`required_event` 绑定真实引擎事件；`condition/effect/false_effect`；`context_val` 引用事件携带的实体与参数；`time_in_future` 延后执行；支持多条 EOC 组合与变量作用域。
- 可借：触发、作用域、条件-效果、可持续/延迟、事件带来的上下文必须可在新规则中访问。
- 不能照搬：游戏偏向末日生存、物品/地图/人物局部交互；没有 1900 年真实地球的户籍、国籍、经济与政治制度；部分 EOC 能力具有过大的作用范围，不能无边界暴露给 LLM。
- **许可证注意：** 项目官方说明代码和数据总体采用 **CC BY-SA 3.0**，包含 share-alike 义务；最新贡献指南明确不接收 LLM 生成内容的贡献。这是我们**参考机制而非直接复制其源码或给其提交生成内容**的重要原因。详见 https://cataclysmdda.org/contributions/ 和 https://github.com/CleverRaven/Cataclysm-DDA/blob/master/CONTRIBUTING.md。

### D. Crusader Kings III ——角色范围与事件分发，非可移植引擎

- 社区脚本信息：https://github.com/jesec/ck3-mod-base/blob/master/base/game/common/on_action/_on_actions.info
- 模组机制：https://github.com/jesec/ck3-modding-wiki/blob/master/wiki_pages/Event_modding.md
- 实际机制：内核触发 `on_birth_child`、`on_death`、`yearly_playable_pulse` 等；Action 会带角色 Scope，脚本决定可触发什么。文档警告在对每位人物调用的周期钩子里再次遍历所有活人，可能引入 N² 级工作量。
- 可借：角色/家族/领地/组织范围；角色拥有任职与权力、继承、复杂关系；以具体事实触发故事，不靠随机日志；按人口范围设置低频脉冲。
- 不能照搬：封建法理与头衔体系不等于 20 世纪国家、企业、党派、军队和福利制度；引擎与商业素材并非开源可移植组件。

### E. FreeSO / SimAntics ——行为队列与对象提供行为

- 仓库：https://github.com/riperiperi/FreeSO
- 实际工程：The Sims Online 的 C# 重实现，包含行为虚拟机/对象交互体系；仓库标注 MPL-2.0，具体代码可查 `FSO.SimAntics` 及相关执行部分。
- 可借：地点/物体/组织向人物**提供具体行为**，有中断、恢复、交互请求、队列；不要给每个人写一份包含全世界所有行为的超级 AI 决策树。
- 不能照搬：房屋局部空间中的高频行为脚本和实时动画，与 30 秒推进一年的跨地区社会史模拟完全不同。应借**语义/调度模式**，不是照搬每秒 Tick 的游戏完整 VM。

### F. RimWorld ——可控事件与外生冲击

- 可参考事件结构：https://github.com/Dev-Jahn/rimworld-modding-reference/blob/main/05-events-incidents/incident-system.md （第三方整理，非官方源代码）
- 具体概念：IncidentDef 的执行器、发生条件、冷却与难度/威胁权重；Storyteller 调节重大事件节奏。
- 可借：外生事件并非总靠个人动作自然涌现；强历史导演可以创造危机、机会与巧合。但本项目不能因“世界不够刺激”每隔几分钟强行投灾祸。
- 不能照搬：RimWorld 的难度调节经常围绕单个玩家殖民地；本游戏是一万人共享且不保护主角的世界，不能专门针对观察者作弊。

### G. OpenVic-Simulation ——开放式宏观人口/经济工程参考

- 仓库：https://github.com/OpenVicProject/OpenVic-Simulation
- 已见事实：该仓库具有 C++ 模拟库、数据加载子模块、headless 构建与单元测试/可选基准流程；使用 MIT 许可证，项目仍在开发。
- 可借：POP/社会阶层与生产模型的状态组织方式、数据校验和无 UI 仿真/基准工具。
- 不应宣称它是可以直接替换现有世界经济的成熟完整组件。技术栈、时代不同，且目前仓库还需实际读更多内部代码才能决定可否移植。

### H. AgentSociety 与 Generative Agents ——LLM 是稀缺认知资源

- AgentSociety 研究：https://arxiv.org/search/?query=AgentSociety&searchtype=all
- Generative Agents：https://arxiv.org/abs/2304.03442
- 研究价值：说明记忆、推理、反思、环境交互的某些能力可由 LLM 支撑；也展示大规模 LLM 智能体的计算与推理代价并不属于普通单机游戏逻辑范围。
- 对本游戏的结论：不让每个角色按月调用 LLM；出生编译、内容族生成、稀有深度重规划和世界导演是优先业务。具体 AgentSociety 吞吐数字只能按论文设备配置理解，不可直接外推至 6 vCPU VPS。

## 2. 历史数据：该拿什么来校准，不该拿什么来播剧本

| 数据 | 适用 | 注意 |
|---|---|---|
| Human Mortality Database https://www.mortality.org/ | 历史不同年龄/性别死亡率、寿命与婴儿风险 | 覆盖国家与年份不一致；不能把有资料国家的率全球照搬 |
| Maddison Project Database 2023 https://www.rug.nl/ggdc/historicaldevelopment/maddison/releases/maddison-project-database-2023?lang=en | 长期经济体量与收入级别，支持地区宏观校准 | 历史经济估算含模型与不确定性；附带 CC BY 4.0 及引用要求 |
| Correlates of War https://correlatesofwar.org/data-sets/ | 国战、外交军事冲突统计和分析框架 | 只能校准战争规模与发生倾向，不能强制未来按史实发生 |
| UN WPP 2024 https://population.un.org/wpp | **1950 年以后**人口宏观趋势对照 | **不覆盖 1900 年开局人口**；不能误称它能直接提供完整 1900 基线 |
| Wikidata https://www.wikidata.org/ | 历史人物名录、出生地、国籍、来源链接等初步索引 | 数据质量与时段误差较大，不能把所有目录人物当活跃模拟对象 |

**真实历史的重建和架空历史必须区分**：1900 baseline 逐项有来源，1900 年以后的历史事件变成条件化历史可能性。Director 的“回归”是创建新的**现实条件**，不是让史实自动复现。

## 5. 交付顺序应按机制闭合，不是按功能数量

| 阶段 | 代码/内容产物 | 必须在同一世界实现的可观察后果 |
|---|---|---|
| I. 社会事实底座 | POP/具名身份一致性、家庭和工作契约、角色权限、事件/状态日志 | 工资、死亡、婚育不重复结算；家庭经济真实影响机会 |
| II. 交互与持续事务 | 行为提供、具体人物选角、请求-答复、事务/项目时间线、认知 | 两个现实人物不靠随机事件也能形成长期关系及合作/冲突 |
| III. 内容运行时 | 受控 EOC/多实体 Effect、角色匹配、延迟进程、版本与索引 | 同一事件族在不同地区、时代、人物上产生不同后果 |
| IV. 出生与祝愿 | LLM 出生推演、Birth Contract、特殊能力、异步编译/入世 | 祝愿能影响实际认知/人物关系，并与真实历史后果交织 |
| V. 20 世纪世界史 | 历史资料基线、战争/经济/政权/健康风险、真实人物活化 | 一项劳动法能改变后来多代人的真实行动选择 |
| VI. 生成式内容工厂 | 批量主题内容、持续动态自动发布、强 Director | 世界出现新技术/组织后事件库自动长出新的现实活动 |
| VII. 完整体验与上线 | 三栏、复杂纸娃娃、因果日志、离线回放、死亡总结、部署监控 | 人生能够从出生到死亡完整阅读，关键经历能追溯真实因果 |

不建议按这个表把系统隔离开发到最后才合并。每阶段需在同一个仓库运行完整跨模块因果场景、形成可复现运行证据；所有调查、单测和恢复工作由 Coding Agent 完成，不应要求玩家每天当测试员。

## 6. 容易误入的八个坑

1. **事件越多越好**：无法被真实角色/时代匹配的内容毫无价值。
2. **地名越多世界越真实**：没有家庭、工作、社会活动场所，7,239 座城市也只是地图点。
3. **所有 NPC 都必须用 LLM**：会击穿成本与可复现性，但不增加同等比例的真正互动。
4. **匿名人口等于不重要人口**：匿名居民必须真实生产、迁徙、死亡并参与组织，不然玩家无法改变历史。
5. **世界导演等于写故事**：导演负责改变世界条件与机会，不是撰写已发生的假历史。
6. **真实历史人物等于目录名称**：历史人物必须有行动窗口、真实社会关系与偏离史实的能力。
7. **异能平衡等于 fame 上升**：隐蔽读心、记忆操控和全球级治疗对世界的外部影响不能靠“被人关注”自动平衡。
8. **加速测试等于降低完整性**：削减人口可以，不能用删掉经济、政治、监护或战争的方式让模拟跑快。
